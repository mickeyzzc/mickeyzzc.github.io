Storage Choices and Memory Budget on a 16 GiB Box
November 4, 2026 · 4 min read

The storage backend decides more than performance — it decides whether migration is a downtime event or a live one. That is the one sentence this post rests on. Along the way: the memory budget for a 16G box, because an uncapped ZFS ARC is a memory thief.

The conclusion first

incus move fundamentally means moving instance disks from A to B:

  • If A and B share one storage (Ceph and friends), no data moves — only runtime state does → live migration, no downtime;
  • With local disks on each node (my case), data is physically copied → downtime migration, seconds to tens of seconds for containers, longer for VMs.

So the first storage question is not “which is fastest” but “am I willing to pay Ceph’s price for zero-downtime migration”. My answer: no. Two 16G boxes cannot carry Ceph’s minimum of 3 monitors + OSDs, and “no mutual replication” makes its replication useless here. Accept the short downtime window on local disks — that is the entire cost.

One UI for Multiple Clusters: What Open Source Offers
November 8, 2026 · 9 min read

The requirement grew: two independent clusters, one per subnet (each starting with a single leader, replicas to follow), one web frontend above both, plus one-click cross-cluster migration. This post separates “intra-cluster migration” from “cross-cluster migration” — they are not the same thing at all — and covers the five hard constraints of going cross-cluster, plus what the open-source survey concluded.

Pinning the topology down

Three layers: a single web frontend at the top (incus-hub / the control plane); below it two clusters sharing nothing — cluster A on subnet 1 (192.168.10.0/24, leader A1 + replica A2) and cluster B on subnet 2 (192.168.20.0/24, leader B1 + replica B2), each internally shaped like the “1 leader + N replicas” from earlier posts. The orange dashed line is cross-cluster migration: copy + delete in essence, with an IP change guaranteed. There is no shared database between the clusters; profiles, networks, and pool definitions are disconnected — that fact creates every difficulty below.

Why evolve incus-hub

Everything v1 has gets reused:

Existing foundationHow v2 uses it
