Four Protocol Libraries, Extracted: ONVIF and GB28181 in Go and Rust

August 29, 2026

MiBee’s camera access runs on two protocols. ONVIF is the de facto standard internationally — Hikvision, Axis, Dahua, and Bosch all speak it. GB/T 28181 is China’s national surveillance standard, unavoidable in government and state-owned projects. The device side (Raspberry Pi camera firmware, one Go and one Rust implementation) and the NVR side (MiBeeNvr, Go) both speak these two protocols, and the stacks have always lived inside the projects. Two problems with that. First, this code is pickled in interop details — digest-auth qop handling, SIP Via-branch uniqueness, MANSCDP element-vs-attribute dual forms, TCP framing header byte counts — each one was ground out against a real platform, and a new project would have to grind them all again. Second, a library survey two weeks ago showed the open-source landscape for these protocols is unevenly populated; several positions have no one standing in them.

Taking Over onvif-go: Real-Camera Fixes, Zero Dependencies, and Service Facades

August 27, 2026

MiBeeNvr talks to cameras over ONVIF, and this library is what sits underneath. ONVIF is the de facto standard for IP video surveillance equipment: device discovery, media profiles, PTZ control, event subscriptions — all one set of SOAP-over-HTTP service conventions. Any brand that claims ONVIF compliance can, in theory, be integrated through the same calls. onvif-go is that stack implemented in Go. We did not write it from scratch: its upstream was 0x524a/onvif-go — the previous author reshaped it into its modern form of a client plus a virtual camera server (the git history still traces back to earlier Go ONVIF attempts in the community). But upstream stalled entering 2026: the last merged PR landed in mid-January, the v1.0-through-v1.1.3 release cadence from late 2025 never resumed, and three Improve Test Coverage issues filed in November 2025 sit unclaimed to this day. Meanwhile we hit two problems in our own camera pool that could only be fixed inside the library.

MiBeeSteward v0.4.0: Router-Resident Discovery + OpenWrt Deployment + Device-Persistence Rewrite

July 29, 2026

When v0.3.0 shipped container images, there was a non-negotiable precondition: the container had to run with --network host to see the full ARP table, otherwise MAC discovery dropped to zero. The root cause was the network namespace — the container couldn’t see the host’s /proc/net/arp packed with 30 rows. v0.4.0 pushes that constraint to its logical conclusion: what if the discovery program runs on the gateway itself? The gateway is the choke point for all LAN traffic. DHCP leases, the conntrack connection table, hostapd’s wireless clients, dnsmasq’s DNS query log — this data is right there, no need to SNMP-poll a switch, no port scanning, zero extra network traffic. This release lets the center or agent reside directly on the router and taps these four passive sources.

MiBeeNvr's AI Detection: Why Inference Runs in the Browser, and Why YOLO11n

July 28, 2026

MiBeeNvr’s Smart Features include an AI detection option that runs inference entirely in the browser — the backend server does no inference at all. The ONNX model file is served to the browser, and ONNX Runtime Web executes it client-side. The model is Ultralytics’ yolo11n.onnx. This isn’t a common choice among NVR products. Most open-source NVRs (Frigate, the go2rtc ecosystem) put AI inference on the backend, because the backend has access to the raw stream, runs persistently, and can use a GPU. Moving inference into the browser is a deliberate architectural trade-off, not a stopgap. This post breaks down two things: why inference lives in the browser, and — given that premise — why YOLO11n.

The /api/cameras endpoint would stall for 14.9 seconds while all 9 recorders started up — not because the traversal was slow, but because the cm.mu RWMutex was blocking, holding every read operation out. ONVIF camera addition still required typing in IP addresses manually, and with a household of CW500s, DS-2CD2047G2s, and others, every new camera meant opening a terminal session — not sustainable. And the older Xiaomi devices — Dafang, Xiaofang, Aqara G2 — couldn’t be integrated at all because they speak the TUTK protocol. None of these are new technical challenges; they’re engineering debt, and v0.9 pays it off in one shot.
