gb28181-go Tutorial: From Device Registration to Platform Ingest

September 30, 2026 MiBeeOSS Go, GB28181, IP Cameras, Open Source MiBee Open Source Projects Series 3069 words 15 min read
🔊

gb28181-go is the only all-in-one volume among the five protocol libraries: the same module carries the device side (UAC, registering a media source to a GB/T 28181 platform) and the platform side (UAS, accepting device registrations and pulling streams from them). The device code came out of the MiBee Eye Raspberry Pi camera firmware, and the platform side was extracted wholesale from MiBeeNvr’s GB28181 access implementation — the two ends bite against each other in production every day.

The two roles are independently usable — camera-firmware authors live in device/, platform builders in platform/ and platform/sip/, with no coupling between them. This post is written to a “copy it and use it” standard: each role goes from project setup to a complete program, every config is documented field by field, and each part lands directly in your own project.

Installation and Project Setup

console
1

mkdir my-gb-camera && cd my-gb-camera
go mod init example.com/my-gb-camera
go get github.com/mickeyzzc/gb28181-go@latest

Go 1.26 or newer is required (the library enforces the 1.26.6 toolchain to pull stdlib security fixes). A few dependencies come down on the first go get: emmansun/gmsm (SM algorithms for GB 35114), ghettovoice/gosip (platform-side SIP only — the device side is hand-written SIP), pion/rtp, and golang.org/x/text (GBK charsets). The manual lives in the MiBee protocol library docs.

Sparring partner: the device side needs a GB28181 platform to talk to — the open-source WVP works fine; for the platform side, any GB28181 camera will do, or run this library’s device side as a fake camera.

package main

import (
	"context"
	"log"
	"os"
	"os/signal"
	"syscall"
	"time"

	"github.com/mickeyzzc/gb28181-go/device"
)

func main() {
	cfg := device.Config{
		Enabled:               true,
		PlatformSIPAddress:    "192.168.1.10",
		PlatformSIPPort:       5060,
		DeviceID:              "34020000001320000001", // 20-digit GB code
		ChannelID:             "34020000001310000001",
		SIPDomain:             "3402000000",
		Password:              "your-platform-password", // digest secret agreed with the platform
		LocalSIPPort:          5060,
		RegisterIntervalSecs:  3600,
		HeartbeatIntervalSecs: 60,
		HeartbeatTimeoutCount: 3,
		Transport:             "udp", // udp | tcp | tls (SIPS)
	}

	// FrameHub is a ready-made FrameSource: bounded channels, drop-on-full
	hub := device.NewFrameHub()

	srv := device.New(cfg, device.DeviceInfo{
		Name:         "Front Door",
		Manufacturer: "MiBee Studio",
		Model:        "MiBee Eye",
	}, hub)

	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	// capture loop: replace with your encoder output; synthetic frames show the shape
	go func() {
		for i := 0; ; i++ {
			au := device.AccessUnit{Timestamp: time.Now(), KeyFrame: i%25 == 0}
			if au.KeyFrame {
				au.NALUs = []device.NALU{
					{Type: 7, IsSPS: true, Data: []byte{0x67, 0x42}}, // SPS
					{Type: 8, IsPPS: true, Data: []byte{0x68, 0xEB}}, // PPS
					{Type: 5, IsIDR: true, Data: []byte{0x65, 0x01}}, // IDR
				}
			} else {
				au.NALUs = []device.NALU{{Type: 1, Data: []byte{0x41, 0x02}}}
			}
			hub.Write(au)
			time.Sleep(40 * time.Millisecond) // 25 fps
		}
	}()

	errCh := make(chan error, 1)
	go func() { errCh <- srv.Start(ctx) }() // blocks: registration, keepalive,
	// catalog answers and INVITE handling all run inside

	<-ctx.Done()
	_ = srv.Deregister(context.Background()) // REGISTER Expires: 0, full 401 dance
	srv.Stop()
	if err := <-errCh; err != nil {
		log.Fatal(err)
	}
}

Walking through it:

  • DeviceID and ChannelID are 20-digit GB codes; 3402000000132 prefixes are the common network-camera flavor, and SIPDomain is usually the first ten digits. Misconfiguration fails fast: Start runs Validate() first, and a wrong digit count errors on the spot.
  • device.NewFrameHub() hands you a FrameSource implementation for free: bounded channels (64 per subscriber by default), drop-on-full. The encoder just calls Write; a slow consumer drops frames rather than blocking capture. For bigger queues use device.NewFrameHubWithSize(size).
  • srv.Start(ctx) blocks in UDP mode — registration, heartbeats, catalog answers, and INVITE handling all run inside its receive loop, and it returns when ctx cancels. Stop with srv.Stop(); for a graceful exit use srv.Deregister(ctx), which walks the full REGISTER Expires: 0 401 dance.
  • In the fed AccessUnit, NALU.Data carries the raw NAL payload without the Annex-B start code, and the IsSPS/IsPPS/IsIDR flags decide how the muxer packs it. Mark them honestly — RTP timestamps and IDR handling depend on them.

// device.FrameSource interface
// Subscribe(ctx context.Context) *FrameSubscription
// Unsubscribe(id string)

type captureBus struct {
	mu     sync.Mutex
	nextID int
	subs   map[string]chan device.AccessUnit
}

func newCaptureBus() *captureBus {
	return &captureBus{subs: make(map[string]chan device.AccessUnit)}
}

func (b *captureBus) Subscribe(ctx context.Context) *device.FrameSubscription {
	b.mu.Lock()
	defer b.mu.Unlock()
	b.nextID++
	id := fmt.Sprintf("sub-%d", b.nextID)
	ch := make(chan device.AccessUnit, 64) // bounded: drop when full, never block capture
	b.subs[id] = ch
	return &device.FrameSubscription{ID: id, Channel: ch}
}

func (b *captureBus) Unsubscribe(id string) {
	b.mu.Lock()
	defer b.mu.Unlock()
	if ch, ok := b.subs[id]; ok {
		close(ch)
		delete(b.subs, id)
	}
}

// broadcasting from the capture side:
func (b *captureBus) broadcast(au device.AccessUnit) {
	b.mu.Lock()
	defer b.mu.Unlock()
	for _, ch := range b.subs {
		select {
		case ch <- au:
		default: // full: drop
		}
	}
}

One rule carries the whole design: subscription channels must be bounded, and a full channel must drop. The library subscribes once per INVITE and unsubscribes on BYE; the encoder’s pace should never be dragged down by a network consumer.

Frame types are AccessUnit{NALUs []NALU; Timestamp time.Time; KeyFrame bool} and NALU{Type byte; Data []byte; IsIDR, IsSPS, IsPPS bool}. Plain H.264 knowledge applies: SPS/PPS go with the IDR (that is how decoders initialize), and honest keyframe flags shape platform-side start-up waits and recording splits.

Registration, Keepalive, Lifecycle

mermaid
flowchart TD
    REG["REGISTER"] --> CH["401<br/>nonce challenge"]
    CH --> RE["REGISTER<br/>+ digest answer"]
    RE --> OK["200 OK<br/>device online"]
    OK --> KA["Keepalive<br/>miss beats → offline"]

    classDef net fill:#FFF3E0,stroke:#E65100,color:#BF360C
    classDef ok fill:#E8F5E9,stroke:#2E7D32,color:#1B5E20
    class REG,CH,RE,KA net
    class OK ok

Digest authentication (MD5 and SHA-256, qop=auth) is fully automatic; Password is the secret agreed with the platform. Two behaviors worth knowing in advance: a failed initial REGISTER does not kill the process — the device drops into listen-only mode and retries on the registration cycle, recovering automatically after network blips; and re-registration with auth happens on schedule, no action needed.

The lifecycle API is five methods: Start(ctx) (blocking), Stop(), Deregister(ctx) (graceful exit), and SIPPort()/SIPTCPPort() (the actually bound ports, useful when LocalSIPPort is 0). To observe the platform’s clock, read srv.PlatformDateUnix() (the SIP-Date header on REGISTER responses — observation only; applying the clock is the host’s call).

package main

import (
	"context"
	"log"
	"time"

	"github.com/mickeyzzc/gb28181-go/gbsip"
	"github.com/mickeyzzc/gb28181-go/platform"
)

func main() {
	cfg := gbsip.Config{
		Enabled:        true,
		SIPListen:      ":5060",
		ServerID:       "34020000002000000001",
		Realm:          "3402000000",
		Password:       "your-platform-password",
		PortRange:      "30000-30050",
		MediaTransport: "udp",
	}

	dm := platform.NewDeviceManager(60 * time.Second) // keepalive liveness window
	bus := gbsip.NewEventBus(64)
	alarmCh := make(chan gbsip.Event, 8)
	_ = bus.Subscribe(gbsip.TopicGB28181Alarm, alarmCh, 0) // alarm events flow here

	ports := platform.NewPortManager(30000, 30050)           // RTP port pool
	sessions := platform.NewSessionManager(ports, cfg.ServerID)
	srv := gbsip.NewServer(cfg, dm, sessions, myDeviceStore) // implement DeviceStore or copy the example

	if err := srv.Start(context.Background()); err != nil {
		log.Fatalf("platform server: %v", err)
	}
	defer func() { _ = srv.Stop() }()

	// once a device is online, pull a stream from one of its channels (two steps):
	// _ = srv.InviteChannel(deviceID, channelID) // idempotent: no re-INVITE on an existing session
	// hub := sessions.GetHub(channelID)
	// _ = hub.Subscribe("recorder", func(pts int64, au [][]byte, isIDR bool) {
	//     // au holds demuxed NALU payloads, isIDR marks keyframes
	// })
	// to stop: _ = srv.ByeChannel(deviceID, channelID)

	select {} // the example runs forever; wire it into your service framework
}

The five pieces each own a slice: DeviceManager keeps the device registry and liveness; EventBus emits events (TopicGB28181Alarm, TopicGB28181SnapshotFinished); PortManager owns the RTP port pool; SessionManager owns sessions and the media hubs; gbsip.NewServer wires them into a complete SIP server. DeviceStore is the persistence seam — eight methods (device/channel CRUD, offline marking, channel-to-camera binding); in-memory and SQLite versions are in the examples.

The full stream path: InviteChannel sends the INVITE (SDP negotiation inside the library), the platform’s NewReceiver ingests RTP from the port pool, demuxes RTP/PS, runs a jitter buffer with SSRC latching, and fans the access units out through the FrameHub from GetHub. The callback signature func(pts int64, au [][]byte, isIDR bool) — pts in milliseconds, au ready-made NALU payloads, straight into your recording or AI pipeline. Slow consumers stay isolated: hub.Dropped() counts drops.

On the device side, receive controls with SetControlHandlers; the full ControlCallbacks set:

Commands without a registered callback get an explicit reject response — never silently swallowed, so the platform can tell the device does not support them. For active device-side reporting (alarms, catalog changes, mobile position) take srv.Notifier() for a DeviceNotifier: SendAlarm/SendCatalogChange/SendMobilePosition go out while the platform has a matching subscription, and are safe no-ops otherwise.

// type RecordingIndex interface {
//     Lookup(startMs, endMs int64) []SegmentMeta
// }
// type SegmentMeta struct {
//     File string
//     StartMS, EndMS int64
//     Size, Frames, Keyframes int

Lookup returns the segments overlapping a time range; the library turns the playback INVITE into paced per-segment reads, packetized at true pace, and sends a MediaStatus: Play Finished SIP INFO when the stream ends naturally (Download Finished for downloads). You provide segment reading; device.OpenSegment is a reference implementation for bare Annex-B plus a millisecond-timestamp sidecar, and device.BuildMediaStatusInfo supports custom completion notices.

2022, Cascade, and GB 35114

  • GB/T 28181-2022: set Config.ProtocolVersion to "3.0" (or "2.0" for 2016) and REGISTER carries the X-GB-Ver header for version negotiation; the platform’s answer is readable via PlatformProtocolVersion(). Unset, the wire format is byte-identical to 2016.
  • Cascade: platform/cascade/ registers this level downward to parent platforms (Upstreams supports several), aggregating catalog upload, INVITE forwarding, and recorded-segment playback forwarding, with multi-level loop prevention and the 2022 Annex H.3 X-RoutePath.
  • GB 35114 A-level: enabled with the build tag -tags gb35114 (the default build has zero SM dependencies), covering SM2 certificate mutual-auth registration plus keyed-SM3 Note-header integrity, on both device and platform.

How Production Projects Use It

Both ends of the library have well-defined production hosts, and the README’s package table names them in the Origin column: the platform-side family (platform/, platform/sip/, psmux/, manscdp/, platform/cascade/, nalutil/) was extracted wholesale from MiBeeNvr’s GB28181 access implementation; the device side, device/, came out of the MiBee Eye Go camera firmware (the current implementation being mibee-eye-go). These two projects are the library’s first users, and every interop fix in the library started as a real-machine problem they reported. Feature by feature:

FeatureProduction projectHow it’s used
Device registration / keepalive / catalog answersmibee-eye-goA Linux board’s UVC camera registered to a GB platform, heartbeating and answering Catalog/DeviceInfo
FrameSource feeding / INVITE streamingmibee-eye-goEncoder output flows through FrameHub; RTP/PS pushes start on INVITE and stop on BYE automatically
Platform five-piece / INVITE pulls / RTP receiveMiBeeNvrAccepts device registrations, invites channels, and feeds demuxed frames into its recording and live-view pipelines
PTZ / playback / talk-back dispatchMiBeeNvrThe platform-side control surface, with RecordingIndex wired to its recording store for playback
CascadeMiBeeNvrRegisters as a lower level to parent platforms, aggregating catalogs and forwarding INVITEs
psmux / manscdpShared by both endsMiBeeNvr’s push side and the device side share one PS/RTP muxer and one MANSCDP codec

Pick your reading by role. Building a camera: read mibee-eye-go — pure Go, zero CGO, UVC capture direct; every device/ seam (FrameHub feeding, control callbacks, the recording index) has matching code in a real product. Building a platform: read MiBeeNvr — a single-binary NVR whose GB28181 access, from the registry up through cascade, is the platform/ family in its original form. For sparring, use WVP or MiBeeNvr as the platform and mibee-eye-go as the device — both start out of the box.

SymptomCauseFix
Registration loops on 401, device never onlinePassword mismatches the platform, or codes/domain are wrongVerify the 20-digit codes, SIPDomain, and secret; run Validate() first

INVITE accepted but no media arrivesNo keyframes fed, or consumers too slow and frames droppedCheck KeyFrame flags and that SPS/PPS ship with IDR; inspect hub.Dropped()
