gb28181-rs Tutorial: Registering a Device to a GB28181 Platform in Rust

October 1, 2026 MiBeeOSS Rust, GB28181, IP Cameras, Open Source MiBee Open Source Projects Series 2405 words 12 min read
🔊

gb28181-rs is the Rust implementation of the GB/T 28181 device side (UAC): register a media source to a national-standard platform, push streams to it, and receive platform-pushed controls. It is a twin of gb28181-go — the same responsibilities in two languages, with PTZ bit decoding, talk-back SDP, and snapshots sharing one set of golden wire-format tables, so whichever packaging drifts turns red first. The library was extracted from MiBee’s Rust camera firmware and runs in production daily.

This post is written to a “copy it and use it” standard: run it with zero hardware first, then build a complete host from cargo new, with a full implementation behind every injection seam.

Installation and Project Setup

console
1
2
3

cargo new my-gb-camera && cd my-gb-camera
cargo add gb28181-rs tokio --features tokio/full
cargo add anyhow log env_logger

The current crates.io release is 0.12.0, and the MSRV is Rust 1.80 (a dedicated CI job watches it). The runtime is tokio; there is exactly one optional feature: gb35114 (SM-security A-level), which pulls SM2/SM3 dependencies and needs Rust 1.85 or newer to build; the MSRV itself stays at 1.80. One caveat: the version numbers in the README’s usage block lag behind — trust the CHANGELOG and crates.io.

Zero-Hardware First Run

Before writing code, watch the library run itself — device_demo is an in-process interoperability demo with a hand-written fake platform (SIP server plus RTP receiver) that walks the full REGISTER → 401 digest challenge → authenticated re-REGISTER → Catalog → INVITE → RTP/PS ingest back to NALUs → BYE loop, asserting at every step. Exit code 0 means the whole stack works:

console
1

cargo run --example device_demo

No real platform, no real camera — one dev machine validates the protocol stack. Three more examples have their own jobs: playback_demo shows record queries and playback control (RecordInfo → playback INVITE → PAUSE/speed → BYE), ps_mux shows offline PS packetization/unpacking (no network), and manscdp_demo shows the pure message-layer codecs.

use gb28181_rs::{AccessUnit, FrameSource, FrameSubscription};
use std::collections::HashMap;
use std::sync::atomic::{AtomicU64, Ordering};
use std::sync::Mutex;
use tokio::sync::mpsc;

struct CaptureBus {
    next_id: AtomicU64,
    subs: Mutex<HashMap<u64, mpsc::Sender<AccessUnit>>>,
}

impl CaptureBus {
    fn new() -> Self {
        Self { next_id: AtomicU64::new(1), subs: Mutex::new(HashMap::new()) }
    }

    // capture-side broadcast: drop when full, never block the encoder
    fn broadcast(&self, au: AccessUnit) {
        let subs = self.subs.lock().unwrap();
        for tx in subs.values() {
            let _ = tx.try_send(au.clone());
        }
    }
}

impl FrameSource for CaptureBus {
    fn subscribe_with_capacity(&self, capacity: usize) -> FrameSubscription {
        let id = self.next_id.fetch_add(1, Ordering::Relaxed);
        let (tx, rx) = mpsc::channel(capacity.max(2));
        self.subs.lock().unwrap().insert(id, tx);
        FrameSubscription { id, receiver: rx }
    }

    fn unsubscribe(&self, id: u64) {
        self.subs.lock().unwrap().remove(&id);
    }
}

Two semantic conventions are visible right in this code: the FrameSubscription{id, receiver} returned by subscribe_with_capacity wraps a bounded channel, capacity 2 by custom, with drop-on-full semantics for slow subscribers; the library subscribes once per INVITE and unsubscribes via unsubscribe on BYE.

use gb28181_rs::{AccessUnit, Gb28181Config, Gb28181Server, Nalu};
use std::sync::Arc;
use std::time::{Duration, Instant};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let mut config = Gb28181Config::default();
    config.enabled = true; // the library never reads it; the host gates startup
    config.platform_sip_address = "192.168.1.10".into();
    config.platform_sip_port = 5060;
    config.device_id = "34020000001320000001".into(); // 20-digit GB code
    config.channel_id = "34020000001310000001".into();
    config.sip_domain = "3402000000".into();
    config.password = "your-platform-password".into();
    config.heartbeat_interval_secs = 60;
    config.heartbeat_timeout_count = 3;

    let bus = Arc::new(CaptureBus::new());

    // capture task: replace with your encoder output; synthetic frames show the shape
    let feed = bus.clone();
    tokio::spawn(async move {
        let mut i = 0u64;
        loop {
            i += 1;
            let key = i % 25 == 0;
            let au = AccessUnit {
                nalus: if key {
                    vec![
                        Nalu { nalu_type: 7, data: vec![0x67, 0x42], is_idr: false, is_sps: true, is_pps: false, is_aud: false },
                        Nalu { nalu_type: 8, data: vec![0x68, 0xEB], is_idr: false, is_sps: false, is_pps: true, is_aud: false },
                        Nalu { nalu_type: 5, data: vec![0x65, 0x01], is_idr: true, is_sps: false, is_pps: false, is_aud: false },
                    ]
                } else {
                    vec![Nalu { nalu_type: 1, data: vec![0x41, 0x02], is_idr: false, is_sps: false, is_pps: false, is_aud: false }]
                },
                timestamp: Instant::now(),
                is_key_frame: key,
            };
            feed.broadcast(au);
            tokio::time::sleep(Duration::from_millis(40)).await; // 25 fps
        }
    });

    let mut server = Gb28181Server::start(config, bus.clone(), None).await?;
    // from here the device is online: registration, keepalive, catalog,
    // and INVITE handling all run in the background

    tokio::signal::ctrl_c().await?;
    server.shutdown_with_deregister().await?; // REGISTER Expires: 0, full 401 dance
    Ok(())
}

Walking through it:

  • Gb28181Config is serde-friendly with TOML and JSON sharing the same shape — the field assignments above are equivalent to deserializing a config.toml. platform_sip_address, device_id, and password are the three must-change fields; the library has start-time checks for exactly these (next section).
  • Gb28181Server::start(config, hub, recordings) binds the SIP socket and runs in the background, returning a ServerHandle marked #[must_use] — drop it and the server has no supervisor. On exit, shutdown() is the fast stop (the registration expires naturally), while shutdown_with_deregister() first sends REGISTER Expires: 0 through the full 401 dance.
  • Frame types are AccessUnit{nalus, timestamp, is_key_frame} and Nalu{nalu_type, data, is_idr, is_sps, is_pps, is_aud}: data carries the raw NAL payload without the Annex-B start code, SPS/PPS ship with the IDR, and is_key_frame must be honest — RTP timestamps and platform-side start-up waits depend on it.
  • While local recording runs, call gb28181_rs::set_record_active(true) so a platform DeviceStatus query honestly reports <Record>ON</Record>.

For tests without a capture bus, the built-in gb28181_rs::MockFrameHub (bounded channel, drop-on-full, with new()/write(&AccessUnit)/subscriber_count()) works out of the box.

The two injection interfaces define only where data comes from: live frames enter via FrameSource, recording indexes are queried via RecordingSource; SIP timing, MANSCDP codecs, and the H.264/H.265 → MPEG-PS → RTP packetization all live inside the library, invisible to the host.

use gb28181_rs::{RecordingSource, SegmentMeta};

struct FsIndex;

impl RecordingSource for FsIndex {
    fn lookup(&self, start_ms: u64, end_ms: u64) -> Vec<SegmentMeta> {
        // query your recording store; return segments overlapping the window
        vec![SegmentMeta {
            file: "/records/1430.mp4".into(),
            start_ms: 51_600_000,
            end_ms: 54_000_000,
        }]
    }
}

// pass Some(Arc::new(FsIndex)) as start's third argument
let server = Gb28181Server::start(config, bus, Some(Arc::new(FsIndex))).await?;

Lookup returns the segments overlapping the half-open query window; the library turns the playback INVITE into paced per-segment reads, packetized at true pace, and sends MediaStatus: Play Finished when the stream ends naturally (Download Finished for downloads); SIP INFO playback control (pause/speed) is handled inside the library. Reading the segment files is the host’s job (resolve_path has a default). Run cargo run --example playback_demo to watch the whole playback interaction sequence.

use gb28181_rs::manscdp::PtzCommand;

struct Controls;

impl gb28181_rs::DeviceControlHandler for Controls {
    fn on_force_iframe(&self) { /* make the encoder emit an IDR now */ }
    fn on_ptz(&self, cmd: &PtzCommand) { /* bit-level decoded PTZ, drive the gimbal */ }
    fn on_record(&self, start: bool) { /* manual recording start/stop */ }
    fn on_guard(&self, arm: bool) { /* guard arm/disarm */ }
    fn on_teleboot(&self) { /* remote reboot */ }
    // on_reset_alarm / on_home_position / on_drag_zoom as needed
}

server.with_control_handler(Arc::new(Controls));

DeviceControlHandler covers force I-frame, recording, guard arm/disarm, alarm reset, remote reboot, bit-level decoded PTZ (sharing the same golden byte table as the Go twin), DragZoom, and HomePosition; DeviceConfigHandler takes basic parameters, frame mirroring, and alarm-report configuration. Commands without a callback keep their explicit reject response — the platform can tell the device does not support them.

server.with_audio_sink(Arc::new(|payload: &[u8], _ssrc: u32| {
    // G.711 payload, feed your audio output

server.with_talkback_source(rx);
// the capture thread pushes 20ms G.711 packets into tx

Without an audio sink, the talk-back INVITE answers 488 — the platform clearly learns the device has no talk-back. For active reporting use server.notifier():

2022 and X-GB-Ver

The GB/T 28181-2022 negotiation switch is one config field:

rust
1

config.protocol_version = Some("3.0".to_string()); // 2022; "2.0" = 2016

With it set, every REGISTER (initial and authenticated re-send) carries the X-GB-Ver header, and the platform’s announced version is readable from server.platform_protocol_version(). Unset, the wire format is byte-identical to 2016 — that’s the default. The 2022 five information-query groups (HomePosition, CruiseTrack, and friends) plus snapshot, subscriptions, and broadcast all have minimal answers. The SIP-Date on REGISTER responses surfaces at server.platform_date_unix() — clock observation only; setting the clock is the host’s decision.

How Production Projects Use It

The library is production code to begin with: extracted verbatim from MiBee’s Rust camera firmware, with mibee-eye-rs and mibee-eye-notebook as the running hosts. Feature by feature:

FeatureProduction projectHow it’s used
FrameSource feeding / registration / INVITE streamingmibee-eye-rsV4L2 capture plus M2M hardware or openh264 software encoding, with the encoder output fed straight into the library — a complete GB camera at roughly 6 MB RSS
Control callbacks / 2022 negotiation / playbackmibee-eye-rsThe full device surface: PTZ and force-I-frame callbacks wired to camera control, protocol_version enabling 2022, RecordingSource backed by local recordings
Talk-back / microphone upstreammibee-eye-notebookA PC’s webcam and microphone become a GB device, with_talkback_source takes the system microphone, and the GB 35114 security feature runs on it

For complete implementations: mibee-eye-rs is the full answer to “turn a Linux board into a GB camera” — capture, encode, feed, register, stream, and play back in one program, with a matching module in it for every seam in this post. mibee-eye-notebook shows the same library running on a PC (a TLS web admin page, with RTSP/RTMP/ONVIF/GB28181 coexisting). When sparring against the Go twin (gb28181-go), the two sides align on shared golden byte tables, so either side works as platform or device.
