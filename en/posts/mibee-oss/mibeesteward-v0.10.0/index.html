MiBeeSteward v0.10.0: When the Network Breaks, Know Which Hop

November 25, 2026 November 26, 2026 MiBeeOSS Go, Network Diagnostics, Observability, NAT, Open Source MiBee Projects Series 1943 words 10 min read
🔊

A slow link, occasional packet loss, a phone that keeps dropping — the probes page used to show one health score. When it fell, you could not tell which vantage saw it, who held the public egress, how far the path got, or whether anything was actually affected. A score says “something is wrong”; it cannot say which hop.

The timeline ends at v0.8.0, and the last release was about device archives. This one is about the network itself: probing grows from a score into a diagnosis system.

Networks get a home

  • The sidebar collapses into five “places”, and Networks is one of them: one page lists every network — egress IP, NAT type, quality, device count, and how the networks interconnect.
  • Drill into a network and the gateway profile, per-vantage quality, interconnects and assets sit together — no more three levels into a device detail page before you can see the egress and NAT type.
  • The inter-network topology is clickable; cross-network RTT, loss and jitter read straight off it.

Dashboard: Networks is a first-class sidebar entry; quality and device state on one screen.

Network Center: overview, detail, inter-network topology and cross-network assets — a read-only aggregation of existing endpoints.

See which hop

  • “Egress & Paths” puts every vantage’s distinct public IPs, their ASNs and the per-hop RTT toward a target on one panel: the center and an agent may see different paths for the same task.
  • A failed probe triggers a rate-limited path snapshot, so you can see how far the path got at the time.
  • Latency breaks into DNS, connect, TLS and response stages; a timed-out run keeps the stages it completed instead of leaving one line of error text.

Probes: Egress & Paths, the site matrix, and the history dialog’s total / stages toggle.

Only report what matters

  • A flaky target no longer raises an alert per run. A degradation episode opens only after network- or path-level cross-confirmation.
  • Attribution is required to notify: an egress identity change, a path change, or other egress groups degrading too. Without that evidence the episode is recorded, not sent.
  • Alerts come in pairs — degradation and recovery — so no string of “failed” events is left without a resolution.
  • Reference targets that are unreachable from some networks by design now read “unreachable”, not 0% · 0ms, so they cannot look like an uninitialized matrix.

No more device splits

  • One physical box split into four rows with sightings at dozens of addresses: the device list now carries “same device” and “multi-homed” badges, with an evidence chain on drill-down.
  • Addresses read from a stale ARP cache are judged separately from “the device actually answered a scan” — the former is never taken as a device changing IP.
  • The gateway row now says “symmetric (EDM)” or “cone (EIM)” inline, instead of hiding it three levels deep.

Device detail: identity verdict badge, evidence chain and per-address liveness timeline.

What the gateway can do

  • Settings gains a STUN list and a one-shot test: one click shows the current public mapping and its RTT.
  • Probing is off by default — the test exposes the site’s public mapping to a third party, so enabling it is your call.
  • The shipped list drops two endpoints measured dead; stored lists reconcile on read, so you will not keep probing addresses that no longer answer.

The timeline ends at v0.8.0, where probing answered “is it up”. v0.9.0 turned discovery into an asset archive. This release pushes probing one layer up: where is the quality problem, and what is the evidence.

Egress and paths: evidence first

Previously the only vantage was the center, egress identity was not recorded, and a path was something you traced by hand during an incident — “failed” and “whose failure” were inseparable. Center and agents now run the same echo rounds (HTTP / STUN / DNS) and a zero-privilege tracer: public IPs are enriched with ASNs via Team Cymru, one entry per transport; the tracer uses TCP connects and ICMP ping sockets, walking hops with IP_TTL / IP_RECVERR and reading reply TTL via IP_RECVTTL — no capabilities required. A failed probe also fires a rate-limited path snapshot. recording only. Egress and route changes never alert on their own; under the impact-first rule they are attribution material.

Degradation episodes: quiet without attribution

Every target used to emit its own failure and recovery — a flaky reference point could produce dozens a day. Now each target × vantage track is judged against its own baseline: a 72-hour median until seven days of history exist, then same weekday × hour buckets, on aligned 15-minute windows, with consecutive degraded windows required. Opening an episode also needs cross-confirmation: most quality references of one egress group degrade (network level), or at least two targets in one /24 degrade from that egress view (path level). Attribution travels inside the episode: same-window egress identity changes, path changes on involved targets, whether other egress groups degraded too, and the dominant failure shape.

alert_requires_attribution defaults on — only attributed episodes fire quality_degraded / quality_recovered; unattributed ones are recorded silently. System quality-matrix targets stop emitting per-target failure / recovery; their tracks feed the detector, while manual and autogen targets keep the old behavior. Boundary: pull-based throughout, including the device identity verdicts.

Burst loss and jitter: catching microbursts

A 60-second probe cannot see microburst loss, and jitter did not exist. icmp targets gain burst_count (1–20 echoes per round) and burst_interval_ms (10–1000 ms apart), reporting loss_pct and jitter_ms (mean absolute difference of consecutive echo RTTs); quality gains the stable codes loss_burst / jitter_high, with thresholds at probe.quality.loss_pct_threshold (default 5) and jitter_degraded_ms (default 30). The window mean runs over every row of a burst target — clean 0% rounds included, or the mean is biased upward.

http targets now run under httptrace, reporting DNS, connect, TLS and wait-for-response stages plus the resolved IP; icmp reports the remaining reply TTL. A timed-out run keeps the stages it completed. What an agent can see through reqwest is only the DNS stage and the resolved IP — documented plainly, not presented as symmetric.

Site matrix and gateway profile

Agent-reported source addresses let the site matrix wire itself: with probe.autogen.mesh_enabled on by default, every autogen sweep reconciles center→agent and agent→agent legs, icmp using a 10-echo burst block, with RTT, loss and jitter readable over a 10-minute window. A leg’s identity comes from its own metadata, never the target name — agent ids may contain -, so string splitting misattributes; a leg whose destination deregistered is dropped rather than left as a phantom column.

The gateway profile is the other half: opt-in probe.nat (off by default) carries the STUN list and one-shot test; agents discover the router through UPnP IGD, then run SSDP M-SEARCH → device description → control URL → GetExternalIPAddress + AddPortMapping SOAP as the capability test, and classify mapping behavior with one socket and at least two distinct STUN servers — identical mappings mean cone / EIM, any difference symmetric / EDM, fewer than two answers unknown, never guessed. Evidence lands in the router device’s scan_attributes.gateway, renders as a Network Profile block, and the verdict is lifted into the device header. The shipped list uses public STUN only (Cloudflare / Google / Nextcloud / Bilibili / Antisip) — the product ships zero self-hosted STUN, a neutrality constraint.

Network Center and device identity

Networks used to be a CRUD table: egress and NAT type were buried three levels into a device, quality, routing and assets were scattered, and there was no view of interconnects. The new read-only /network-center has four layers — network overview, per-network detail, inter-network topology and cross-network assets. It is pure frontend aggregation of existing endpoints: no new schema, no new API.

“The device keeps changing its IP” used to be unanswerable: one physical box split into a bond MAC row, a wifi MAC row and MAC-less mDNS ghosts, and searching it showed unrelated rows. A new verdict engine joins sightings (device_sightings), per-IP scan liveness (scan_snapshots), multi-homed presence and the change stream into verdicts with evidence: stale_arp_scan_artifact (many sighted addresses, none answering a scan — the sightings came from stale ARP cache reads, not a moving device), multihomed_alias, locally_administered_mac, ip_slot_takeover, hostname_identity_split. Sightings alone are ambiguous, so every address is cross-checked against snapshot miss / flap counters before a verdict is issued. The same verdict is lifted onto list badges, from the same rules as the detail engine so the two never disagree.

Two dead STUN endpoints

The shipped probe.nat list carried Tencent and Xiaomi endpoints. Five RFC 5389 Binding Requests from each of two vantages answered 0/5 on both — Tencent had already been dropped from the P2P platform’s production config while we kept shipping it; Xiaomi was dead too. Nextcloud flapped between 2/5 and 5/5 across vantages. Both were replaced with endpoints measured alive: Bilibili (4/5, about 45 ms from both) and Antisip (5/5).

The hard part: probe.nat lives in the system_settings overlay, not YAML, so no installer migration can reach it. Left alone, an old overlay keeps probing dead nodes; and an overlay missing a newly shipped builtin gets rejected 400 on its next save by the “builtin cannot be removed” gate, with no visible cause. Read-time reconciliation fixes it: drop builtins no longer shipped, append newly shipped ones, let shipped labels win, preserve the operator’s enabled flag on survivors, and never touch user rows. Idempotent — a list already in shipped shape comes back unchanged.

Implementation details

Config keys: probe.egress.* (echo sources and cadence), probe.trace.* (per-hop tracing, Linux-only trace capability on agents), probe.nat (STUN list and one-shot test), probe.quality.* (thresholds and episodes), probe.autogen.mesh_enabled (self-wiring matrix), and the Web switches for probe.quality / probe.autogen.

Endpoints: GET /probe-egress, GET /probe-paths, GET /probe-targets/{id}/paths, POST /probe-targets/{id}/trace, GET /api/v1/probe-matrix?window=, GET /api/v1/probe-quality/episodes, GET /api/v1/probe-targets/{id}/phases, GET /api/v1/devices/{id}/diagnosis, GET|PUT /api/v1/settings/probes, GET|PUT /api/v1/settings/probes/stun-servers.

Probe extensions live in a side database, data/probe_ext.db (the heartbeat.db pattern — additive DDL, no SchemaVersion bump), swept by retention.probe_ext_days; probe_phases, quality_episodes and vantage_hostnet are there. HostNet facts in vantage_hostnet come from agent samples every five minutes: per-interface rx/tx error and drop counters (a counter going backwards means an interface reset, not a regression), the default-route fingerprint, and one DNS resolution against the center — riding meta.hostnet, with center-side deltas decorating degraded vantages with vantage_local_degraded.iface_errors / route_change. The SNTP offset (meta.clock_offset_ms) lands in agent_status.sntp_offset_ms.

agent-rs reaches 0.2.4: UDP DNS makes up to three attempts inside the timeout budget (same socket, fresh transaction id so a late reply to an earlier attempt cannot satisfy a later one), fixing false timeouts against high-loss upstreams; the DNS decoder follows chained compression pointers (16-jump cap), and http probes send the product identity MiBeeSteward-probe/<version>. Older agents keep reporting; the new capabilities need 0.2.4 for full fidelity.

Upgrading

Schema v9 → v10 → v11; crossing a version is still a database rebuild: back up with scripts/backup.sh, remove the old database, start fresh, rescan to repopulate. Probe history series reset; archive entries do not survive the rebuild and re-accrue as devices cycle offline. Within v11, minor upgrades are a binary swap.

On binary/systemd and Docker upgrades, flip the two probe switches in Settings, or follow doctor’s hint to restore the quality matrix — an absent probe.quality key now defaults ON. OpenWrt kept-config upgrades auto-add the default blocks via migrate-config.sh. Upgrade agents to 0.2.4 together. deb / rpm, the OpenWrt package trio and GHCR images ship in this release.
