视觉模型看图与看录像能力调研：哪些已解决，哪些是全行业边界

October 23, 2026 October 24, 2026 AI工具 视觉模型, Video-LLM, 多模态, 目标跟踪, ReID, 选型调研 AI 工程实践和调研系列 4939 字 10 分钟阅读
🔊

假设你接到一个需求：一万小时的监控录像，要能回答两类问题。第一类：“这个人是谁"“这辆车去哪了"“他几点进的机房”。第二类：“他在机房里做了什么"“从哪个时刻开始动手的"“他拧螺丝的动作快不快”。

这两类问题都叫"视觉理解”，但答案的命运完全不同。第一类在公开数据集上已经打到饱和，工程上属于成熟可交付；第二类是 2026 年全行业的能力边界——最强的闭源模型也过不了及格线，而且这不是"再多等半年"能解决的。这篇把两类能力的现状、边界在哪、正确架构长什么样、钱怎么算、开源许可有哪些坑捋一遍。数据核实于 2026 年 10 月；所有榜单分数都注明了口径，因为这里的数字水分比大多数领域都大。

把"看懂"拆成六层

“视觉模型能不能看懂视频"这种问题没法回答，得先拆。业内按任务分层：

层级任务输入输出成熟度
L1 图像感知分类、检测、分割、OCR单帧框、掩码、文本高，工业级
L2 身份与属性人脸比对、行人再识别、属性单帧或行人图身份、相似度高（公开集饱和）
L3 跨帧关联多目标跟踪、跨镜头追踪连续帧轨迹 ID高（遮挡换装受影响）
L4 动作与事件动作分类、起止时间定位视频片段动作类别 + 时间区间中
L5 场景结构镜头边界、精彩片段整段视频分段、摘要中高
L6 语义理解视频问答、以文搜视频长视频 + 指令自然语言、时间码中低，长时序弱

几个术语就地解释：行人再识别（ReID）指跨摄像头认出"这是同一个人”——不认识他是谁，但能从一百路摄像头里把他的轨迹串起来；多目标跟踪（MOT）指在连续画面里给每个人一个稳定的编号，不因为遮挡就换号；时间定位（temporal grounding）指回答"这个动作从第几秒开始、持续到第几秒”。

关键区分在 L2/L3 和 L4/L6 之间：前者回答"这是谁、他去哪了”，靠的是逐帧特征比对；后者回答"他在做什么、何时开始的”，靠的是时序建模。两类技术栈完全不同，不能互相替代——这个区分贯穿全文。

看图：认人认物基本解决了

先说好消息。静态图上的识别任务（L1/L2）已经是成熟工业：

任务公开基准公开成绩口径注意
人脸 1:1 比对LFW99.5%–99.85%基准已饱和，区分不出好坏模型
人脸 1:N 检索IJB-C约 87% @ 千分之一误识率协议敏感，全量微调和零样本差异大
行人 ReIDMarket1501mAP 94–96必须声明是否用了重排序（一种后处理，能把分数再抬 2 个点）
行人 ReID（更难）MSMT17mAP 77–87更接近真实跨镜头场景，参考价值更高

mAP 是检索任务的标准指标，可以粗略理解为"要找的人排在结果前列的程度"。注意 Market1501 这个数字的读法：网上流传的"mAP 0.96 所以人脸识别已解决"混淆了两件事——公开集饱和不等于你的场景已解决。风险不在精度，转移到了三处：数据合规（人脸是敏感生物特征，采集存储都有法定义务）、活体防伪（照片和视频回放能骗过纯算法）、跨镜头域偏移（你的摄像头角度、光照、清晰度和训练数据不一样，现场精度会掉一截）。

工程结论：身份类需求直接用成熟方案（InsightFace 一系的开源模型，或商用 SDK），把预算花在防伪和合规上，别花在刷精度上。

看录像：三套基准给出同一个答案

现在到坏消息，也是这篇最重要的部分。“看懂连续动作、判断何时发生”（L4/L6）是当前全行业的能力边界。证据不是某一家模型的短板，而是三套互相独立的学术基准指向同一结论：

基准测什么人类最强模型说明
TimeBlind时间盲测：何时开始、多快、先后98.2%Gemini 3 Pro 48.2%、GPT-5 46.3%细粒度时序无一过 50%
MotionBlind纯运动理解（自录视频防数据泄漏）—仅 Gemini 3.1 Pro 整体及格，速度判断仍失败；开源模型贴 6.25% 随机线样本仅 60 实例，方向可信但别过度外推
Video-MME-v2严格协议下的综合视频问答90.7%最强闭源 49.4%、最强开源 39.1旧协议下全体被高估约 17 分

这三套基准的设计不同（语义组合、物理运动、组级一致性），但结论一致：模型"看的不是运动"，而是帧内容加语言先验。直白点说，模型抽几帧看到"一个人躺在地上、旁边有水杯"，用语言常识猜"他滑倒了"——它没有真正追踪过滑倒这个过程。把帧打乱、甚至把视频拿掉只给文字描述，很多模型的答案变化不大。

对选型的直接影响：

  • 需要"何时开始、持续多久、多快"这类时间精度，用专门的时序定位模型（ActionFormer 一类），别指望 Video-LLM
  • 需要"数出来几个人、搬了几箱货"这类计数，当前模型接近随机（有基准实测实例计数类只有 7–18% 正确率）
  • 需要速度方向判断（正常/异常驾驶、动作快慢），目前没有能用的通用模型
  • 需要"发生了什么"这类语义，Video-LLM 明显好于规则引擎——它的主场在这里

另外一个常见的分数陷阱：厂商发布会引用的 Video-MME 87%+ 这类成绩，榜单页面自己标注"仅供参考、以厂商自报为主"。验收永远用自有数据测，这类分数连参考基线都算不上。

正确架构：两条流水线各干各的

既然单条技术线覆盖不了六层能力，生产系统的做法是双层。看动画：

上层是判别式流水线：检测（YOLO、RT-DETR 这类模型，画出每个人每辆车的框）→ 跟踪（ByteTrack、BoT-SORT，把框串成轨迹）→ ReID（跨摄像头串联同人）→ 动作/时序定位（专门的小模型）。它精确、实时（边缘设备跑得动）、可解释（能指出结论来自哪几帧的哪个框），缺点是只认预定义类别——训练时没见过"未戴安全帽"，它就永远报不出来。

下层是 Video-LLM（视频多模态大模型：Gemini、Qwen3-VL、Kimi 这些）：抽帧压缩后喂给大模型，用自然语言问答。它零样本（没见过的行为也能描述）、能跨片段推理、能"帮我找有人摔倒的那段"，缺点恰好互补：速度计数不可靠、时间码不精确、按 token 收费。

两层各自评测、最后融合：时间轴交给上层（精确到秒），语义描述交给下层（自然语言），报告里合并。反过来做——用 Video-LLM 出时间码、用判别式模型写描述——两头都是最差的。

长视频：问题变成"怎么省着看"

一段 1 小时的视频，Video-LLM 怎么"看"？现实是抽帧看：默认每秒抽 1 帧，每帧转成一定数量的 token（大模型处理信息的最小单位，计费也按它）。以 Gemini 官方口径算账：低分辨率档每秒约 100 token，默认档每秒约 300 token——1 小时视频默认档约 108 万 token，已经顶着 1M 上下文的上限。这就是长视频的瓶颈：不是"能不能看"，是 token 预算撑不撑得住。

2026 年三条主流的省法：

路线代表机制效果（含口径）
Agent 式按需取帧Gemini 的 agentic 模式（仅 Flash 系）先低帧率扫全片，对关键片段再高帧率回看长内容 token 最多降 88%（厂商"up to"口径）
编解码原生选块微软 Mage-VL（论文阶段）用运动矢量能量挑高信息量的块，替代均匀抽帧token 降 75% 以上（论文自报）
多帧压缩MiniCPM-V 4.5 的 3D-Resampler6 帧压成 64 个 token约 96 倍压缩（4.5 专属；4.6 是 1.3B 端侧模型，4/16 倍可切换）

工程上不依赖单一路线的通用做法是分段摘要 + 按需回取：先把长视频切成段（镜头边界检测是成熟技术），逐段摘要存索引，用户提问时只回取相关段的高帧率原文。这和 RAG（检索增强生成）处理长文档是同一个思路。

开源许可的三个坑

这条线的开源生态有一个特点：代码宽松不等于能商用，坑密度比一般领域高。三处最典型的：

YOLO 是 AGPL。 Ultralytics 官方许可页写得很清楚：AGPL-3.0 有传染性，即使模型自己训练、只在公司内部用、不对外发布，也要求整个项目开源，否则买 Enterprise 授权。很多团队拿 YOLO 训了个内部检测模型就上线，这是在许可上裸奔。替代：RT-DETR、D-FINE 都是 Apache-2.0。

SAM 3 的许可不是开源许可。 Meta 的分割模型 SAM 3/3.1 用自定义 SAM License：免版税但带用途限制（军事、武器等场景禁止）、权重要 gated 申请、发表需署名。如果只接受标准开源许可，用 SAM 2.1（Apache-2.0）。

论文许可不等于权重许可。 视频自监督模型 V-JEPA 2 的 GitHub 仓库主体是 MIT（三个工具文件 Apache-2.0），但网上流传"论文 CC BY-NC-ND 所以不能商用"的说法查无实据，而且即使论文带非商用许可，也推不出权重非商用——两者是不同的东西。商用前直接向权利方确认权重条款，别靠推断。

API 成本：三种计费口径

调用闭源视觉模型，计费口径有三种，先换算再比较：

产品计费换算参考
Gemini按 token默认档约 300 token/秒视频；1 小时约 108 万 token
火山引擎（豆包系）Aideo按片源时长多模态理解 0.08 元/分钟；高光分析 1 元/分钟
Twelve Labs Pegasus按输入视频时长输入 1.75 美元/小时，输出按 token 另计

隐藏成本项：抽帧在服务端做的（传视频 URL）和在自己端做的（传图）价格结构不同；输出 token 通常比输入贵好几倍，让模型"详细描述每一分钟"的账单会教你做人。

按场景选型

场景推荐理由
门禁、考勤人脸 SDK + 活体检测成熟区，重点在防伪合规
园区找人找车检测 + 跟踪 + ReID + 向量库跨镜检索靠特征比对，不靠大模型

媒资打标、内容理解Video-LLM + 镜头切分 + 分段摘要语义强、结构化输出好

几个常见疑问

让模型数"画面里有几个人"行吗？ 单帧、目标稀疏时勉强可以；连续计数（总共进来几个人、搬了几箱）接近随机。计数用检测模型逐帧数再 dedup，别用大模型。

模型给的时间码能信吗？ 秒级引用经常偏。要精确时间轴就用时序定位模型，Video-LLM 的时间码当索引用（帮你跳到大概位置），别当证据用。

公开榜单分数能写进验收标准吗？ 不能。自报成绩、协议差异、数据泄漏三重水分。正确做法：自建 50–200 条"金标片段集"（自己标注答案的测试题），感知/时序/运动三类分开出题，每次换模型换采样率都重跑。

全上开源还是全上 API？ 精确层（检测跟踪 ReID）本地跑——便宜、实时、数据不出域；语义层按量调 API——省 GPU、跟上模型迭代。两层分开决策，不要绑死一家。

想动手试试，从哪开始

  • 想快速体验 Video-LLM 的边界：拿一段体育比赛或工地操作视频，分别问"他做了什么动作"（大概率答对）和"这个动作持续了几秒、比上一次快还是慢"（大概率翻车）——两分钟的实验胜过读十篇评测
  • 想本地部署：Qwen3-VL（Apache-2.0，全尺寸）或 MiniCPM-V 4.6（1.3B，笔记本可跑）起步
  • 想搭精确层：RT-DETR + BoT-SORT + FastReID 全部 Apache/MIT 系许可，MMAction2 里有现成的动作识别时序定位实现
  • 想做选型 POC：按上面的双通道设计跑一次横评——30 段自有视频，判别式通道测身份轨迹精度，LLM 通道测语义问答，各自出分数再决定配比
