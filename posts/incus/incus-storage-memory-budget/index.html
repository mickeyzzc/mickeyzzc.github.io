16 GiB 小机器的存储选型与内存预算

November 4, 2026 November 9, 2026 虚拟化与运维 Incus, ZFS, Btrfs, 存储架构 自托管运维手记 1716 字 4 分钟阅读
🔊

存储后端决定的不只是性能，还有迁移是停机还是在线这件事——这是这篇最重要的一句话。顺带把 16G 机器的内存预算算清楚：ZFS 不限量就是隐形内存刺客。

一个先行的结论

incus move 的本质是把实例磁盘从 A 搬到 B：

  • 如果 A、B 是同一份共享存储（Ceph 这类），数据不用搬，只搬运行时状态 → live 迁移，不停机；
  • 如果是各自本地盘（我的场景），数据要实打实拷贝 → 停机迁移，容器几秒到几十秒，VM 更久。

所以存储选型的第一问不是「哪个快」，而是「要不要为零停机迁移付出 Ceph 的代价」。我的答案：不要。两台 16G 扛不住 Ceph 至少 3 monitor + OSD 的开销，而且「不互备」根本用不到它的多副本。接受本地盘的短停机迁移，这就是全部代价。

驱动对比

驱动特点迁移友好度16G 场景评价
ZFS写时复制，原生快照/压缩/配额，zfs send/receive★★★（send 加速停机迁移）数据重要、有 SSD、愿意调 ARC 就选它
btrfs写时复制，内核自带，低内存开销★★★不想调内存就选它，最省心
LVM块设备卷，性能好★★已有 LVM 布局才考虑
dir普通目录存磁盘文件★（纯文件拷贝）纯试水
Ceph分布式共享池，多副本★★★★★（live 迁移）⚠️ 2×16G 不划算，别碰

上图是每台 16 GiB 节点的内存切分：宿主系统 2 GiB、ZFS ARC 封顶 4 GiB、实例可用 9~10 GiB、预留 buffer 1 GiB；下面单独一条是 4 GiB swap。底部是存储驱动的迁移友好度对比——本地存储一律停机迁移，只有共享存储（Ceph）才能 live，数据要实打实拷贝，ZFS 只是拷得更快。

内存预算（每台 16G）

用途额度说明
宿主系统 + incusd + dnsmasq1.5~2 GiB留足，别挤
ZFS ARC2~4 GiB（必须封顶）不限的话默认可吃一半以上内存
实例可用9~10 GiB两台合计 ≈ 20 GiB
预留 buffer≥ 1 GiB启动突发、快照、迁移拷贝
Swap4 GiB（物理分区）别放 ZFS zvol 上，有死锁风险

ARC 封顶上一篇给过命令（/etc/modprobe.d/zfs.conf 里 zfs_arc_max=4294967296），这里补一个日常验收：

bash
1
2
3

arc_summary | head -20
cat /sys/module/zfs/parameters/zfs_arc_max    # 4294967296
zpool status && zpool list

如果不想背 ARC 这笔开销：把 preseed 里的 driver: zfs 换成 driver: btrfs，ARC 直接归零，btrfs 的快照/压缩能力对这个规模也够用。16G 小机器上这是完全正当的选择——ZFS 不是信仰，是权衡。

为什么选 ZFS（以及它真正的价值）

  1. 原生快照秒级、几乎零成本 → 变更前 incus snapshot 一把，回滚就是一条命令；
  2. 透明压缩：镜像和实例磁盘普遍能省 20~40%；
  3. zfs send | zfs receive：让 incus move 的停机迁移比纯文件拷贝快得多——同样停机，窗口短很多；
  4. 快照调度交给 Incus 托管：
bash
1
2
3

incus config set c1 snapshots.schedule "0 3 * * *"
incus config set c1 snapshots.pattern "auto-{{ creation_date }}"
incus config set c1 snapshots.expiry "7d"

（{{ creation_date }} 是 Incus 的快照命名占位符，给 Incus 的字面配置，Hugo 不会动它。）

有独立数据盘的话

16G 小机器如果系统盘就是一块小 NVMe，preseed 里用 loop 文件（size: 40GB）做池性能一般。有独立盘就整块给池：

bash
1
2

incus storage create local zfs source=/dev/sdb --target incus-n1
incus storage create local zfs source=/dev/sdb --target incus-n2

会清空该盘，注意确认设备名。

最后一遍强调

本地存储的现实是：实例的数据只在一台机器上。挂一台，那台的实例就下线——要么等它回来，要么从备份重建。这是后面「不互备更要勤备份」的伏笔，也是系列最后一篇运维兜底的主角。

驱动特性与迁移行为依据 Incus 官方文档 storage drivers 与实例迁移说明，2026-11 核对。
