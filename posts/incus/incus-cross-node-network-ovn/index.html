迁过去网不通？两个 incusbr0 的二层陷阱

November 5, 2026 November 9, 2026 虚拟化与运维 Incus, 网络, OVN, Bridge 自托管运维手记 1809 字 4 分钟阅读
🔊

集群组好了、incus move 也顺了，然后撞上组集群后的第二个大坑：实例从 node1 迁到 node2，IP 一变、网络一断，「迁移成功」瞬间变成「迁移事故」。这篇讲清楚为什么，以及三条解法里我为什么选 OVN。

坑在哪：名字一样 ≠ 同一张网

incus admin init 默认给每台节点建一个本机托管的 bridge——incusbr0。两台都叫这个名字，但它们是两个互不相连的二层广播域：

  • node1 的实例拿 10.10.11.x，node2 的实例拿 10.10.12.x，各自 NAT 出网；
  • n1 上的容器和 n2 上的容器，哪怕路由都配好也互相 ping 不通（除非走宿主路由绕出去再回来，绕且慢）；
  • 实例迁移到另一台后 IP 必然变化，上层配置（DNS、反代、防火墙）要跟着改。

上半部分是默认状态：两台节点各自的 incusbr0（10.10.11.0/24 与 10.10.12.0/24）之间是断开的二层域，实例互相 ping 不通。下半部分是解法：实例挂到 OVN overlay（各成员装 ovn-* 组件 + OVS，Geneve 隧道走 UDP 6081），跨节点二层互通，迁移后网络身份跟着走；备选方案是两台各建 br0 桥物理网卡。

这个坑和迁移的关系是乘法：迁移本来就有停机窗口，如果迁完网还不通，可用性损失是双份的。所以「随意迁移」要想真正成立，网络必须先解决。

三条解法

方案 A：物理网卡桥接（双节点最简单）

两台各建一个 br0 桥到上行物理网卡，实例直接进物理二层，从上联路由拿管理网 IP：

bash
1
2
3
4

# 先用 netplan/NetworkManager 把物理网卡桥成 br0，再交给 Incus：
incus network create br0 bridge bridge.external_interfaces=enp1s0 \
  ipv4.address=none ipv6.address=none
incus profile device set default eth0 parent=br0

优点：跨节点天然互通、迁移 IP 不变、无额外组件。缺点：实例直接暴露在管理网；操作时小心先把管理 IP 挪到 br0 上再断物理口，别把自己踢下线（建议接显示器或带外）。

方案 B：分子网 + 静态路由（可行但繁琐）

保留各自 incusbr0，两台宿主互指静态路由、关 rp_filter：

bash
1
2
3

ip route add 10.10.12.0/24 via 192.168.10.12 dev enp1s0   # node1 上
ip route add 10.10.11.0/24 via 192.168.10.11 dev enp1s0   # node2 上
sysctl -w net.ipv4.conf.all.rp_filter=0

能通，但 IP 仍会变（跨子网），非对称路由要自己兜，配置繁琐。小环境不值得。

方案 C：OVN 分布式网络（我选它）

OVN 是 Incus 集群原生支持的 overlay 网络：一个跨节点的逻辑交换机，实例挂上去之后二层互通，迁移到哪个节点，网络身份跟着走：

bash
1
2
3

# 前提：各成员装 ovn-* 组件 + Open vSwitch 3.3+（OVN 24.03+）
incus network create ovn0 --type=ovn
incus launch images:debian/13 web01 --network ovn0

代价要如实说：OVN 需要 OVN central DB（两节点只能放其中一台，没有容错位置，是个单点）；Incus 7.0.2 对 OVN 的要求是 Open vSwitch 3.3 / OVN 24.03。对「愿意用一点复杂度换迁移后网络零重配」的场景，它是对的选择。

迁移与网络联动验证

bash
1
2
3
4

# 建 OVN 网络 → 起一个实例 → 迁移 → 确认 IP 不变、业务不掉
incus launch images:debian/13 web01 --network ovn0 --target incus-n1
incus move web01 --target incus-n2
incus list            # web01 在 n2 上 RUNNING，ovn0 下发的 IP 保持

顺手记几个网络相关的运维点

服务暴露：7.0.2 新增了 incus port-forward，比老的 proxy device 省事：

bash
1
2
3

incus port-forward create incusbr0 8080 tcp 10.10.11.5 80
# 老办法（仍可用）：
incus config device add c1 web proxy listen=tcp:0.0.0.0:8080 connect=tcp:127.0.0.1:80

端口清单（防火墙放行口径）：

端口协议用途
8443TCP/HTTPS集群 API、成员心跳、Web UI——仅管理网，绝不裸公网
8444TCP/HTTPS可选 metrics 独立端点——仅监控机
6081UDPOVN Geneve 隧道——节点间
67/68, 53UDPdnsmasq（托管 bridge 内）

同机跑 Docker 的一个暗坑：Docker 会把 FORWARD 链默认策略设成 DROP，实例可能突然断网。确保 net.ipv4.ip_forward=1，或在防火墙里给 incusbr0 到外网口放行。

小结

  • 默认 bridge 是每台各管的二层孤岛，迁移前先把网络方案定了；
  • 要「迁移后零重配」：OVN（本系列选择）或物理桥；
  • OVN 解决的是集群内部跨节点互通——两个集群之间的网络问题，11-08 那篇会再回来收拾它。
