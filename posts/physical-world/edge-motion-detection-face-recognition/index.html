运动侦测与人脸识别：边缘设备上从传统方法到轻量 AI 的资源-精度权衡

在树莓派、IPC 的 SoC、或者一个只有零点几 TOPS 的 AI 盒子上做运动侦测和人脸识别，真正难的不是"能不能做"，而是"用多少资源做到什么精度"。算力和内存预算一旦定死，每个选择都是在回答同一个问题：这一档资源能解决什么，解决不了什么，要补上那个缺口得付出多大代价。

这篇按"资源消耗从低到高"的顺序把两条链路（运动侦测、人脸识别）各走一遍。每一档先说传统方法能干什么、硬伤在哪，再说哪个轻量模型恰好补上那个硬伤、精度如何。文末给按算力分档的选型决策树。

运动侦测：资源消耗的四个台阶

运动侦测的本质是从连续帧里分离"前景运动目标"和"静止背景"。场景越复杂（光照变化、动态背景、抖动），需要的算法越重。按资源从低到高，大致是四级。

台阶一：帧差法（无模型，资源最低）

对相邻帧做灰度差分，超过阈值的像素就是前景。三帧差分取 |f(t)-f(t-1)| 与 |f(t+1)-f(t)| 的交集，能补掉两帧差分的"空洞"。

  • 能做：极低功耗下的实时"有没有动"。1080P 能跑到 80–120 fps，内存十几 MB。
  • 硬伤：静止目标会消失（人停下不动就检测不到）、有空洞、对噪声敏感。

这是零模型方案的天花板——便宜，但停下来的目标看不见。

台阶二：背景减除（主流，补掉空洞与动态背景）

维护一个背景模型，当前帧减去背景得到前景。差别在背景模型怎么建。

  • ViBe：非参数模型，每个像素维护 N 个随机采样样本（论文默认 N=20, R=20, #min=2, φ=16）。核心是整数比较 + 随机采样，没有浮点运算，ARM NEON 友好，缓存命中率高——这是它适合嵌入式的根本原因。资源在背景减除里最低。硬伤：依赖第一帧的纯净度（建议前 30–100 帧不更新模型或用中值初始化），光照突变容错弱。
  • MOG2（混合高斯 GMM）：每个像素用 3–5 个高斯建模，动态更新权重。动态背景适应好、有自适应方差、内置阴影检测。资源中等，1080P 约 45 fps。
  • KNN：每像素维护历史值队列，用 K 近邻距离判断。动态背景适应最好、能抓住短暂停留物体，但内存明显高于 MOG2（具体倍数随 history、混合数配置变化，没有固定比例）。

下面这张表把"传统方法的硬伤"和"哪一级能补"对上，这是选型的关键：

硬伤帧差ViBeMOG2KNN光流轻量 AI
静止目标丢失✗✗✗部分✓✓

注意一个共同点：所有背景减除类方法都对"静止目标"无能为力——目标停住就会被吸进背景模型。要解决它，必须跨到 AI 那一档。

台阶三：光流（最高精度，最重）

追踪像素级运动向量，能拿到运动方向和速度，精度最高。Lucas-Kanade（稀疏）轻一些，Farneback/DIS（密集）重。光流的资源开销大，密集光流尤其重，一般只在高性能设备或需要精细运动场分析时用。

台阶四：轻量 AI（补传统方法的硬伤）

传统方法的精度上限有限，复杂场景（遮挡、小目标、多人、需要分类）下吃力。深度学习能补，但代价是资源。思路是用轻量目标检测网络替代或辅助背景减除：

方案参数量精度（mAP@0.5）边缘部署补上的硬伤
YOLOv5s + ShuffleNetV2 主干~0.24M~92%极佳小目标、分类
YOLOv5s（原版）~7.2M~90%良好通用目标检测
NanoDet + 注意力~1M~88%极佳移动端实时检测

混合流水线：把 AI 的精度塞进传统的资源预算

边缘上最务实的不是单跑 AI，而是两级级联：传统方法做廉价的第一级筛选，只在有运动的区域跑 AI。

效果是把深度学习的计算量砍掉一大块——AI 只在前景区域跑，而不是全图。实测在 Jetson Nano 这类设备上，整体处理速度比全图跑 AI 提升数倍，精度基本不掉。

人脸检测：精度与资源的刻度尺

人脸识别分两步：人脸检测（找到脸在哪）→ 人脸识别（判断是谁）。两步用不同模型，资源和精度差异巨大。检测这一步，模型按"参数量/mAP"排成一把刻度尺。

模型年份参数量mAP（WIDER Hard）边缘适用备注
Viola-Jones（Haar 级联）2001极小远低于深度学习可用但过时传统方法，姿态/光照一变就崩
MTCNN2016~百万级~75%（第三方复测）可用三级级联，含 5 关键点；原始论文报的是 FDDB 而非 WIDER
BlazeFace2019极小（数十万级）—极佳Google 为手机设计，短程 128×128，GPU 亚毫秒；体积很小
SCRFD-500M20210.57M68.5%极佳0.5 GFLOPs，最低档
SCRFD-2.5G（无关键点）20210.67M77.9%优秀无关键点版
SCRFD-2.5G_KPS20210.82M77.1%优秀含 5 关键点（识别对齐用）
SCRFD-10G20213.86M83.1%良好高精度档
YuNet202375,856（~0.076M）~70.8%极致OpenCV Zoo 原生支持，权重亚兆字节级
RetinaFace（R50）2019~25–30M~91%（需额外训练数据）重小脸/遮挡最强，需 GPU

几个容易踩的坑：

  • YuNet 的"81% mAP"查无出处。OpenCV Zoo 模型卡的 WIDER Hard 数字约 70.8%，部分本地复测能到 75% 左右；网上流传的 81.1% 找不到来源，别直接引。它真正的卖点是参数极少（7.6 万）、权重不到 1MB、OpenCV 原生加载，在"够用"的前提下资源压到极致。
  • SCRFD 的"2.5G"要分清有没有关键点。SCRFD_2.5G（0.67M、77.9%）是不带关键点的；带 5 关键点的 SCRFD_2.5G_KPS 是 0.82M、77.1%。识别流程要用关键点做对齐，选带 _KPS 的版本。
  • RetinaFace 的 91% 顶配依赖额外训练数据。裸的 RetinaFace-R50 在 WIDER Hard 上到不了 91%；这个数字是加额外数据训练出来的，且模型 100MB 量级、边缘 CPU 要几百毫秒，基本只能在服务器或有 GPU 的边缘盒子上跑。

人脸识别：特征向量的代价

识别这一步把检测到的人脸映射成一个固定维度的特征向量（embedding），用向量距离判断身份。

    A --> E["CNN 特征提取 → 512/128 维向量"]
    E --> L["L2 归一化"]
    L --> M["余弦相似度匹配特征库"]
    M --> R["阈值判断 → 身份 / 未知"]

不做关键点对齐，识别精度会掉 15–20%。匹配用 L2 归一化后的余弦相似度：sim = dot(query, gallery) / (‖query‖ × ‖gallery‖)，阈值通常落在 0.5–0.65。

模型LFW 精度模型体积特征维度边缘适用许可证
FaceNet99.63%35–220MB128（原版）/ 512（常见复现）重研究
ArcFace ResNet-50/10099.8%166–249MB512重研究
MobileFaceNet~99.5%~4MB512极佳研究
SFace99.40%~37MB（INT8 ~19MB）128优秀Apache-2.0（可商用）

几个要点：

  • MobileFaceNet 不是 1MB。它的 512 维模型参数不到 100 万，FP32 体积约 4MB（INT8 后更小）；网上"1.1MB"的说法对不上参数量。LFW 约 99.5%，是边缘识别的常用解。它用全局深度可分离卷积（GDConv）换的是精度，不是砍参数，“GDConv 砍 78% 参数"的说法没有出处。
  • 要可商用，看 SFace。ArcFace / MobileFaceNet 多为研究许可，商用有风险。SFace 在 OpenCV Zoo 明确 Apache-2.0，LFW 99.40%、INT8 约 19MB，是边缘上"合法可商用"的现实选择。

阈值是另一个要按场景调的参数：安防/高安全用 0.6–0.7（接受略高拒识率），门禁考勤 0.5–0.6，一般识别 0.4–0.5；签发多年的证件照要再降 0.03–0.05 补偿年龄变化。注册时每人存 3–5 张不同光照/角度的特征向量，比存图片更省存储也更合规。

推理框架：选对模型之后还得选对运行时

同一个模型，不同框架的实测性能差很多。

框架来源库体积ARM 性能NPU 支持定位
NCNN腾讯700KB–3MB极佳有限零依赖、ARM 极致优化
MNN阿里3–6.5MB极佳全面异构计算、低功耗
TFLiteGoogle~8MB良好最全面（NNAPI）NPU/DSP 生态最好
OpenVINOIntel较大良好（x86）Intel VPUIntel 平台最优
ONNX Runtime微软中良好CUDA/TensorRT跨平台一致性

一个提醒：MNN"比 TFLite 快 1.8×/3.5×“是阿里自己的基准，方向大致成立（社区复现也认为 MNN 在 ARM 上确实快），但精确倍数是厂商话术，别当成独立测量的硬数字。NCNN 在骁龙 888 上跑 YOLOv5s “28ms” 同理——是社区调优的典型值，不是官方承诺。

框架选型速查：iOS 用 Core ML；Android 高通/联发科用 MNN 或 NCNN；有 NPU（华为/瑞芯微）用 TFLite（NNAPI 覆盖最全）；Intel 边缘盒用 OpenVINO；要零依赖就直接 OpenCV DNN 加载 ONNX。

模型压缩：INT8 是首选，别轻信"组合使用率 67%”

当现成轻量模型仍超预算，压缩能再压一档。

转换体积压缩加速精度损失备注
FP32 → FP1650%1.5–2×可忽略有 FP16 支持的 GPU
FP32 → INT875%（4×）2–4×通常 <1%ARM/NPU 首选；PTQ 一般 <1%，要 <0.5% 得上 QAT
FP32 → INT487.5%4–8×1–3%极致压缩，需校准
  • INT8 量化的精度损失说”<1%“更稳。训练后量化（PTQ）对小于 1B 参数的模型一般能压在 1% 以内；要做到教程常说的”<0.5%“通常得用量化感知训练（QAT），不是免费午餐。
  • 剪枝：通道剪枝能再去掉 30–40%（精度损失 <0.5%），结构剪枝要重训。
  • 知识蒸馏：用大模型当老师训小模型，能把压缩后的精度往回拉。

网上有个说法"知识蒸馏 + 量化 + 剪枝的组合使用率达 67%"——这个数字查不到任何调查或行业报告来源，更可能是个编出来的统计，别引用。三者确实常组合使用（蒸馏保精度 + 剪枝瘦身 + INT8 加速），但不要给它安一个假的百分比。

极限资源：ESP32-CAM 这类 MCU 摄像头

把资源再往下压一档，就到了「摄像头 + 单片机」一体的最低档——ESP32-CAM（ESP32 双核 240MHz、520KB SRAM 加外挂 PSRAM、没有 NPU）。这正是前面决策树里「＜0.5 TOPS」那档的真实硬件，值得单独说清楚它能干什么、干不了什么。

运动侦测：固件里做像素级帧差（两帧灰度差 → 阈值 → 形态学去噪 → 多帧确认）完全跑得动，QQVGA/QVGA 下实时。这是 ESP32-CAM 的主战场——MCU 不够跑背景模型，所以「动一下就触发」是它最自然的用法。ViBe 理论可行，但每像素 N 个样本 × 全图对 PSRAM 带宽和实时性不友好，实战多退回帧差。

人脸检测：ESP32 没有 AI 加速器，但 Espressif 的 ESP-WHO 库提供了为 ESP32 量化的 MTMN 检测网络（MTCNN 的轻量替代），QVGA 下能做低帧率人脸检测。ESP32-S3 有向量指令、配 ESP-DL 能上稍大的量化模型（如 SCRFD-tiny）；带 KPU 的 K210 这类则更宽裕。

人脸识别：在 ESP32-CAM 上做完整的「检测 + 对齐 + 512 维特征 + 匹配」非常吃力，一般只做「检测 + 跟踪」。Espressif 自家的 face_id 能在小库上做识别，但库容量和精度都有限，拿来做考勤/门禁级别要谨慎。

落到工程上，这类极限摄像头最常见的形态是「端触发 + 网关识别」：ESP32-CAM 负责运动/人脸触发和抓拍，通过 Wi-Fi/MQTT 把 ROI 或 JPEG 推给有 NPU 的边缘盒子（或服务器）跑 MobileFaceNet/SFace 做识别。这其实就是前面「混合流水线」的跨设备版——第一级塞进几 KB RAM 的单片机，第二级交给有算力的盒子。

平台档代表运动人脸检测人脸识别
MCU 摄像头（无 NPU）ESP32-CAM帧差 + 形态学ESP-WHO MTMN（低帧率）只做触发，识别上云/网关
MCU + 轻量 AI 加速ESP32-S3（ESP-DL）、K210可上 ViBe量化 SCRFD-tiny小库识别可行
0.5–2 TOPS树莓派、IPC SoCViBe / MOG2YuNetMobileFaceNet

组合方案参考

把上面几段拼起来，边缘上典型的一套是：运动侦测用 ViBe（无浮点）筛 ROI → 只在 ROI 上跑 YuNet 检人脸 → MobileFaceNet（或可商用的 SFace）提取特征 → 余弦相似度匹配。整套模型体积可控制在个位数 MB，内存几十 MB，端到端每帧十几到几十毫秒，刚好落在资源受限设备的预算里。
