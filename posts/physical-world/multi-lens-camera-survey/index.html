把一只眼睛闭上，眼前的世界不会消失，但你对距离的判断立刻变得不可靠——轮流闭左右眼，眼前的东西还会"跳"。这个跳动的量叫视差（disparity），人脑拿它判断远近，双目摄像头拿它算距离。单张照片没有深度，所以"摄像头量距离、辨真假人脸"的本事，都要靠额外手段把深度找回来；多镜头是最直接的方案。手机人脸解锁、扫地机避障、车载环视、门禁刷脸模组，背后都是同一套原理。

一张照片为什么没有深度

相机成像是一次投影：三维世界里一个点 (X, Y, Z)，穿过镜头落在成像平面上，变成 (fX/Z, fY/Z)——深度 Z 在投影的那一刻被除掉了。方向相同、远近不同的两个点，会落在同一个像素上。单看一张照片，你说不出那个点是 1 米外还是 10 米外：一个方程，三个未知数，无解。

所以摄像头要拿到深度，只有三条路，后面所有方案都能归进这三类：

  • 多拍一张：从第二个视角再拍一张，靠两个视角的几何关系解出深度（双目、多目）；
  • 主动打光：向场景投出已知形状的光，看它回来时变成什么样（结构光、ToF）；
  • 靠先验去猜：用训练出来的知识，从单张图的线索估深度（单目深度估计）。

先讲最经典的第一条。

单目：识别"猜"与网络"估"

单目没有第二个视角，但两条路都能"感知"距离。

第一条是识别 + 先验尺寸：先用目标检测认出"这是一辆小汽车"，再用"小汽车一般 4.5 米长"和它在图里占多少像素，按相似三角形反推距离。问题是它只认识训练库里出现过的类别，对没见过的东西无能为力，而且越远精度越差。监控里做目标检测、车牌识别、行为分析，这条路的"分类"部分够用，但不要指望它给出精确距离。

第二条是单目深度估计：让神经网络直接从一张图预测每个像素的深度。这里要先分清两个概念：

  • 相对深度：只保证"谁近谁远"的排序正确，不知道绝对是多少米；
  • 度量深度：输出带真实米制尺度的深度，能直接回答"3 米还是 30 米"。

机器人规划、自动驾驶这类要"按米数做决策"的场景必须用度量深度（或相对深度加相机内参换算），否则不知道障碍是 3 米还是 30 米；AR 抠图、照片 3D 化这类场景相对深度就够。监控场景里更常用的目标检测、人脸识别这些单目任务的模型选型，我在运动侦测与人脸识别那篇里按算力分档梳理过，这里不重复。

双目：把视差量出来，距离就出来了

两台相机并排放，镜头光心之间隔一个固定的水平距离，叫基线（baseline，记作 B）。同一个空间点在左右两张图里的水平像素位置会差一段，这就是视差 d。用相似三角形一推，距离就出来了：

text
1

Z = f × B / d

f 是相机焦距（标定出来的，单位是像素），Z 是物体到相机的距离。举个例子：f = 700 像素，基线 B = 6 厘米，某个点视差 d = 35 像素，那它距离 Z = 700 × 60 / 35 = 1200 毫米，一米二。

你自己就能演示视差：伸直手臂竖起一根手指对准远处的物体，轮流闭左右眼——手指相对背景会明显跳动；再把手指凑近鼻尖重复一次，跳动幅度大得多。近，视差大；远，视差小。双目摄像头做的就是把这种"跳动"逐像素量出来。

图里上方是两个物体点，下方是左右两台相机，中间那条横线是成像平面。同一个点在左右成像面上的投影位置差了一段，这段就是视差：近处物体的视差（橙色标注）明显大于远处物体（紫色标注）。有了视差，Z = f × B / d 一步算出距离。

精度随距离平方衰减

双目有个绕不开的物理规律。把公式变形一下就能看到：距离每放大 10 倍，视差就缩小到十分之一，而同样 1 个像素的视差测量误差，折算成的距离误差按 Z² / (f·B) 放大——距离 ×10，误差 ×100。

还是上面那套参数（f = 700 像素、基线 6 厘米）：在 1 米处，1 个像素的视差误差对应约 2.4 厘米的深度误差，做避障、量身高都没问题；到 10 米处，同样的 1 个像素误差对应约 2.4 米——量到这个距离上，结果已经没法用。基线十几厘米的消费级双目，规律相同。要测远，要么加大基线（镜头分得更开），要么换主动方案。这是几何决定的，不是代码优化能解决的。

四个环节一句话说清：标定用棋盘格同时求出两台相机各自的内参、畸变和相互之间的旋转平移，重投影误差 RMS 小于 0.5 像素算可用、小于 0.2 算干净；校正把两幅图重投影到同一平面，让同一个点落在同一行像素上，匹配从二维搜索降成一维，计算量大幅下降；匹配逐像素在另一幅图里找对应点，输出视差图；深度计算套 Z = f × B / d 得到深度图或点云。

匹配算法最常见的两个选择：BM（块匹配）快、但边缘毛糙、弱纹理区失效；SGBM（半全局匹配）计算量约是 BM 的 5 倍，但抗弱纹理、边缘干净得多，是最常用的折中。深度学习方案（RAFT-Stereo、CREStereo、IGEV-Stereo、FoundationStereo）精度和泛化更好，但要 GPU。用 OpenCV 还有个必踩的坑：StereoSGBM 输出的视差是 16 位定点数，真实值要除以 16。

双目的失效场景

视差的本质是"在另一张图里找到同一个点"，所以找不到对应点的地方深度就是错的：

  • 无纹理：白墙、天空，左右图长得一模一样，没法找对应；
  • 重复纹理：百叶窗、栏杆、条纹，容易匹配到错的重复单元上；
  • 遮挡、反光、透明：一侧能看到、另一侧被挡住，或玻璃上根本没有稳定的像；
  • 视差趋零：远处 d 只剩一两个像素时，1 个像素的误差就把深度带飞——裸视差图永远不能直接给下游，必须先做阈值过滤和滤波（中值、形态学闭运算这类）。

产品形态：被动双目与主动双目

  • 被动双目：纯自然光，结构简单、成本低，但吃纹理、吃光照。消费级代表如 ZED 2i：配默认 2.1mm 镜头测 0.3–20 米，换 4mm 镜头能到 35 米，近距精度约距离的 1%。
  • 主动双目：在双目基础上加红外补光，解决暗光和低纹理的痛点，代价是户外强光下补光被淹没、测距范围受限。代表：RealSense D400 系列、OAK-D 系列。

三目、四目：两种完全不同的"多目"

看到"三目摄像头"先别急着想到立体视觉，它有两种完全不同的含义。

车载语境里的三目是三个不同焦距的单目：广角管近距盲区、主摄管中距、长焦管远距识别，自动驾驶方案里挡风玻璃三摄就是这种配置。它们各拍各的，靠分工覆盖全距离，本质是"单目多焦"。而多目视觉测量指的是多视角立体（Multi-View Stereo，MVS）：三个以上视角的几何约束互相印证，减少双目里的误匹配，再用光束平差把精度提上去——代价是计算量上升。经典的开源实现是 COLMAP（SfM + MVS），它也是 NeRF、3D Gaussian Splatting 这些神经重建方案训练前的位姿估计前置。做新视角合成（NeRF/3DGS）时输入是"一组有重叠的照片"，走的就是这条管线。

NVR 场景下还有个朴素形态的多目：多路网络摄像头本来就是"多机位单目"，靠时间同步和视角互补覆盖全景；想做人或车跨机位的连续跟踪，需要给各机位标定外参，再接多目标跟踪，MiBeeNvr 侧的实践见MiBeeNvr 接入 YOLO 检测。另外多摄协同要发挥作用，相机间同步精度得做到微秒级，靠软件时间戳做不到，得用硬件触发。

主动深度：结构光与 ToF

结构光是向场景投射一副已知编码的红外图案（点阵、条纹），图案打到物体表面会发生形变，解码形变就能算出深度。它给每个投影点自带"身份标签"，不需要像双目那样逐像素匹配。近距精度能到毫米级，部分旗舰手机的人脸解锁和线下支付终端用的就是结构光。短板：有效距离短（米级以内），户外强光会把投射图案淹没。

ToF（Time of Flight，飞行时间）直接测光往返的时间：iToF 测调制光的相位差，dToF 直接计时光脉冲。响应快，中远距可用，扫地机器人、平板对焦常用。短板：透明和高反射材质不稳定，还有多径干扰（光弹到多个面回来，时间对不上号）。

四条路线放到一张表里看：

技术原理主动光源精度特点主要短板代表

怎么选其实就三个变量：要多准、测多远、光照多差。近距高精度（人脸、支付）选结构光；中远距要快选 ToF；宽场景通用且预算有限选双目，暗光多就上主动双目。

选硬件：快门、动态范围、接口与算力

决定深度的算法讲完了，但挑摄像头模组时下面这些参数同样影响成败。

快门。卷帘快门逐行曝光，拍到高速运动或相机自己在动时，画面会出"果冻效应"——竖直的东西被拉歪。它便宜、弱光表现好，静态或慢速场景首选；全局快门所有像素同时曝光，动态场景时间一致性好，代价是更贵、感光度略逊。经验规则：机器人、车载前视、抖动平台这种"相机或目标在动"的场景选全局快门；固定机位拍静态目标卷帘即可。环境光可控的话，用频闪照明（曝光瞬间打亮）也能让卷帘"冻结"运动。

动态范围（WDR）。逆光下人脸全黑、背景过曝，靠它解决。做人脸识别的门禁建议 90dB 以上，车载要求 120dB 以上。

视场角与帧率。窄角 60° 以下适合远距抓拍，门禁常规 60–90°，车载全景 140–180°；常规监控 30fps，运动抓拍要 60fps 起。另外白天色彩和夜间红外不可兼得，靠 IR-CUT 滤光片切换：白天挡掉红外保色彩，夜视模组则保留红外。

接口。

边缘算力。深度估计和立体匹配都是算力大户：RK3588 这类 NVR 级 SoC 能硬解 32 路 1080p30、硬编 16 路（8K@30 编码），给 AI 推理留出余量；Jetson 这类带 GPU 的边缘盒子跑深度学习立体匹配更合适；树莓派 5 则适合 BM 这类轻量算法的原型验证。嵌入式摄像头模组本身的 Sensor、接口、时序细节，iot 分类那篇嵌入式摄像头模组参考整理得更细。

人脸识别模组：存的不是你的照片

多目摄像头目前最大宗的消费级应用，是门锁、门禁、考勤里的双目活体人脸识别模组。门禁"唰"地认出你，它记住的是什么？直觉答案是照片。实际上，模组在录入的瞬间就把图像扔了，只留下一串 128 到 512 维的数字向量。这个设计不是偷工减料，是被安全、存储、隐私三头逼出来的——把这件事讲透，模组的其他参数就都好理解了。

录入时，模组把人脸图像喂给特征提取网络，得到一个高维向量（embedding），原始图像随即丢弃，之后所有比对都发生在这个向量上。它存的不是压缩照片，也不是加密照片，而是从原始面部信息中提取的单向数学描述——即使有人拿到存储器里的文件，也无法逆向恢复成一张人脸图像。

为什么必须做到"不可逆"？因为脸和密码有本质区别：密码泄露了可以改，脸泄露了没得换。生物特征是一次性资产，所以行业的做法是三条铁律：

  • 数据最小化：能不拍就不拍，拍了提完特征立刻丢；
  • 本地比对：特征只在设备内部比对，出口只有一个"通过/不通过"，系统侧拿不到原始特征；
  • 加密存储：模板写入 Flash 前加密，比对在隔离区完成。

不同模型输出的向量维度不同，一条模板的大小也随之不同：

反过来看这个表能发现一件事：容量上限低不是存储不够，是产品定位——100 人的模板只占 200KB，任何模组的 Flash 都装得下几万条，卡在 100 人是厂商按产品档次切的。这里顺便辟个谣：网上流传"入门双目模组能存 10 万人脸"的文章，同批内容还编了"双核 400MHz"“三摄像头"这类参数，是 AI 拼凑的；在售模组的官方口径是 FM225/FM223 存 100 人、FM888 存 500 人、TX510 存 1000 人。选型时以官方参数页为准，别引用二手文章的容量数字。

每步一句人话：

  • 拍摄取像：双目模组同时取可见光和红外两路图像，单目只有可见光一路；
  • 人脸检测：找到画面里的脸，输出人脸框和眼角、鼻尖这些关键点；
  • 对齐归一：按关键点做仿射变换，把脸摆正、缩放到 112×112 的标准尺寸，消除姿态和距离的影响；
  • 活体判断：判断镜头前是真人还是照片、屏幕、面具。注意这一步在特征提取之前——活体不过直接拒绝，根本不进入比对，这是门禁和支付级产品的关键设计；
  • 特征提取：对齐后的图过特征网络，变成 128–512 维向量；
  • 比对决策：1:1（这个人是不是自称的 TA）或 1:N（TA 是库里哪位），算余弦相似度或欧氏距离，过阈值才放行。阈值定在哪，直接决定误识率（FAR，把别人认成你）和拒识率（FRR，把你拒之门外）的平衡——金融级阈值严、门禁级松一些，“秒开"体验和安全性就是在这拉扯。

各环节用什么检测、特征模型，参数和算力怎么排，运动侦测与人脸识别那篇里按资源消耗分过档，这篇不展开。

真正的分水岭：认脸容易，认"活人"难

前面六步里，检测、对齐、特征、比对这四步，普通单目 RGB 摄像头全能做：一块 K210、或单板机加 USB 摄像头，配上 MobileFaceNet 就能跑离线 1:1 识别。单目能"认脸”，这一点没有争议。

问题出在活体。照片、手机、平板回放，在单目镜头里都是平面 2D 图像，和真人脸"看起来一样平”。这不是理论风险：2026 年 4 月，京津冀三地消协的比较试验里，30 款智能门锁有 3 款被一张打印照片开锁、12 款被复制的 IC 卡解锁；2019 年那轮测试更夸张，38 款样品里 32 款被假指纹破解。产品方为了"秒开"体验把识别阈值调低，算法分不清真人平面和照片平面，就是这类事故的直接原因。

单目也能做活体，但手段有限：要么做静默活体（分析纹理、摩尔纹、屏幕反光），要么做动作配合活体（“请眨眨眼”）。它们能挡住低成本的攻击，挡不住屏幕高清回放和 3D 面具。

方案原理抗照片抗视频抗 3D 面具成本
静默活体（单目 RGB）纹理/摩尔纹分析中低–中低极低
动作活体（单目 RGB）指令配合（眨眼/张嘴）高中低低
双目红外深度 + 红外皮肤纹理极高高中中
3D 结构光红外点阵重建 3D极高极高极高高

双目为什么是物理门槛

双目活体模组（一个可见光摄像头加一个红外摄像头，配红外 LED 补光）靠两路信号封死攻击路径：

  1. 深度。两个镜头有物理间距，能算出鼻梁、眼窝、颧骨的高低起伏。真人脸是立体的，照片和屏幕是平面——平面的深度值处处相同，毫秒级就能识破。
  2. 红外皮肤纹理。红外光打在真皮肤上会产生特定散射（毛孔、汗毛），纸张和 LCD/OLED 屏幕没有这个特性。手机屏幕播放的人脸在可见光下可以乱真，在红外通道下立刻露馅。
  3. 暗光可用。红外通道不依赖环境光，夜间、背光场景照常工作，这是单目可见光方案给不了的。

厂商口径里，这类双目活体对照片攻击的拦截率接近 100%、对视频和面具在 99.5% 以上；FM223 的官方标称是活体攻击通过率与活体误拒率均不超过 1%。数字是营销口径，量级可信，采购时应当实测。

结构光和 ToF 走的是另一条主动路线：结构光靠数万红外点阵重建 3D 模型，抗面具最强；ToF 靠光往返时间建深度图。它们和双目红外的共同点是：都需要专用硬件。深度和红外信息是普通 RGB 摄像头在物理上捕捉不到的，任何"纯软件活体"都只是在 2D 信息里打转，防御等级上不去。

双目活体模组：产品形态与选型

市面上这类模组分两种产品形态，先分清这个再谈型号：

  • 算法一体机：模组内置识别算法和封闭协议，主控通过串口拿结果。接入快、改不了算法，门锁门禁厂商几乎都用这种。
  • 裸双目模组 + SDK：只卖彩色 + 红外双路 UVC 摄像头（一两百到三百多元），配独立 ISP 和开发包，检测、活体、比对全要自己做。灵活，但要养算法。

TX510 换了整套芯片方案：TX510 AI 芯片（算力 1.2T@8bit），RISC32 核，跑 RTOS，1000 人库比对 1 秒内、上电 1 秒内启动。接口最全（UART、USB、MIPI、I2C），板上还有三个实体按键——注册键短按注册（脸凑近 50cm）、识别键识别、注册键长按 6 秒清空全部记录，不写一行代码就能完成台架验证。

模组对接：串口协议、帧格式与代码

这类模组在通信里都是从设备：主控（你的 MCU 或网关）发命令，模组执行并回结果。物理层高度统一——UART 115200，8 数据位，1 停止位，无校验（8N1）；视频另走 USB（UVC 协议）输出给屏幕或猫眼。协议层就五花八门了，上面那张表里的七个型号就跑了三套互不兼容的协议：

协议族适用型号帧风格校验
A. FM22X / AI-xxFM223/225/226/888、AI-10二进制：Sync + MsgID + Size(2B) + DataXOR 异或
B. TX510TX510二进制：Sync + MsgID + Size(4B) + Data累加和
C. FR1002FR1002文本 AT 指令无

协议 A 和 B 帧头都是 0xEF 0xAA，但 Size 字段长度和校验算法都不同，帧结构互不兼容；协议 C 是纯文本，串口助手就能调试。下面分别拆开。

协议 A（FM22X / AI-xx）：异或校验

帧结构（主控发命令、模组回消息共用）：

text
1

0xEF 0xAA | MsgID(1B) | Size(2B, 低字节在前) | Data(N) | XOR(1B)

校验字节是从 MsgID 开始到 Data 结束逐字节异或。复位命令（无数据）的实际帧是 EF AA 10 00 00 10——0x10 ^ 0x00 ^ 0x00 = 0x10，手算就能验证。

模组往回发的消息分两类，解析时必须区分：NOTE 是实时状态流（上电就绪、录入过程中人脸的位置和姿态——界面上"往左一点、凑近一点"的提示就靠它），REPLY 是命令执行的最终结果。常用命令（字节级细节以随模组的手册为准）：

命令MsgID说明
RESET0x10复位
GET STATUS0x11查状态
VERIFY0x12识别，参数含超时秒数
ENROLL0x13分方向录入人脸
DELETE USER / DELETE ALL0x20 / 0x21删指定用户 / 清空
FACE RESET0x23终止录入并清状态
GET VERSION0x30固件版本
INIT ENCRYPTION0x50初始化 AES 加密

三个实操坑，都来自厂商 FAQ：

  1. 上电等就绪：模组上电后约 400ms 才初始化完成，期间发命令没有响应；就绪后模组会主动发 READY 类通知，收到再发命令。
  2. 照片注册后别急着断电：照片注册的用户首次识别成功时模组会补全红外模板，手册要求延时 5 秒再断电，否则模板没写完整。
  3. 别信二手资料里的帧格式：网上流传过"0xA5 帧头 + CRC16"的错误描述，与官方手册和多个第三方实现都不符。对接前用串口助手抓一次实帧，以手册为准。

协议 B（TX510）：累加和校验

三套里帧结构最规整的一套，推荐先吃透它：

text
1

0xEF 0xAA | MsgID(1B) | Size(4B, 大端) | Data(N) | Checksum(1B)

校验字节是除帧头外所有字节累加和的低 8 位。注册命令的实际帧 EF AA 13 00 00 00 00 13（Size=0，累加和 0x13），删除用户 1 的帧 EF AA 20 00 00 00 02 00 01 23（Size=2，数据 00 01，累加和 0x23）——两帧都能手算复核。识别（0x12）、删除用户（0x20）、清空（0x21）都有现成 MsgID；指令不存在时模组不回复，调试时"没反应"先查帧格式和校验。

返回帧里带结果码：0x00 成功、0x01 未检测到人脸、0x03 姿态角度过大、0x06 2D 活体未通过、0x07 3D 活体未通过、0x08 比对失败。结果码把"没人"“活体没过"“比对不中"分开报，排查体验比协议 A 细。

协议 C（FR1002）：AT 指令

文本 AT 指令，三步注册流程：AT+REGFACE 启动采集、模组返回二进制特征包，AT+WRITEFACE=<uid> 把特征写入指定用户，AT+READFACE=<uid> 读出已注册特征（格式为用户 ID + 长度 + 特征流）。特征是 128/256 维向量，二进制加密、不可逆，默认不存原始图片。识别成功可直接输出开关量，驱动继电器开门。

接线与供电：三个容易翻车的点

  • 电平：模组 UART 是 3.3V TTL，接 5V 单片机要加电平转换，直连有风险。
  • 供电：FM225 这类模组明确要求电流不低于 1A，用开发板 3.3V/5V 引脚直接供电很容易带不动，电压不稳会导致识别异常或反复重启。FR1002 供电宽（5–14V）但也按手册给足电流。
  • 视频和命令是两条路：命令和识别结果走 UART，彩色视频走 USB（UVC）。别在串口里等视频流——它不在那儿。

import serial

SYNC = b'\xEF\xAA'

# ---- 协议 A（FM22X）：Sync + MsgID(1) + Size(2, 小端) + Data + XOR ----
def pack_a(msg_id: int, data: bytes = b'') -> bytes:
    size = len(data)
    frame = SYNC + bytes([msg_id, size & 0xFF, size >> 8]) + data
    xor = 0
    for b in frame[2:]:
        xor ^= b
    return frame + bytes([xor])

# ---- 协议 B（TX510）：Sync + MsgID(1) + Size(4, 大端) + Data + 累加和 ----
def pack_b(msg_id: int, data: bytes = b'') -> bytes:
    body = bytes([msg_id]) + len(data).to_bytes(4, 'big') + data
    return SYNC + body + bytes([sum(body) & 0xFF])

ser = serial.Serial('/dev/ttyUSB0', 115200, timeout=1)
ser.write(pack_a(0x11))                  # 协议 A：GET STATUS
ser.write(pack_a(0x12, bytes([0, 10])))  # 协议 A：VERIFY，超时 10 秒
ser.write(pack_b(0x20, bytes([0, 1])))   # 协议 B：删除用户 1

# ---- 协议 C（FR1002）：文本 AT 指令 ----
ser.write(b'AT+REGFACE\r\n')             # 启动注册，模组回传二进制特征包
# 写入/读出特征：AT+WRITEFACE=<uid> / AT+READFACE=<uid>

解析回包时，协议 A 要区分 NOTE 实时流和 REPLY 最终结果，协议 B 按 Size 收满整帧再验校验和，协议 C 按行读、特征包按长度读。无论哪套，都等上电就绪通知再发命令。

资料与延伸

双目从标定到匹配的完整操作，OpenCV 官方文档的 Stereo 一节是标准起点：docs.opencv.org；单目深度估计各模型的权重都在 Hugging Face 上可以直接拉下来跑。模组侧的字节级协议格式，各家的手册不公开在网页上，向供应商或代理商索取开发手册 PDF 是唯一可靠途径——网上二手文章的帧格式常有错漏（本文提到过的"0xA5 + CRC16"就是一例），拿到手册后先抓实帧核验一遍再动手写代码。
