双光谱热成像的嵌入式落地：从机芯到 NVR

October 13, 2026 October 24, 2026 物理世界开发 热成像, 双光谱, 嵌入式, NVR, 图像处理 信号与图像处理系列 6097 字 13 分钟阅读
🔊

上一篇把双光谱热成像的原理、NVR 配套和产品格局捋了一遍。这一篇动手：假设你手上有一块热成像机芯（比如艾睿的 640×512 模组，或者一块 FLIR Lepton），目标是一台能被 NVR 正常管理的双光谱相机。中间要过的坎按顺序是：图像管线、测温链路、双光配准、多路编码、平台协议、智能分析和测试验收。

热成像机芯和可见光传感器各自成像，进同一颗 IPC SoC（海思 Hi3516DV500、星宸、瑞芯微这类，双 MIPI 输入是硬需求），SoC 负责热像处理、配准融合、双路编码、测温计算和事件上报，最后以 RTSP/ONVIF 或国标出流给 NVR。选 SoC 时值得知道瑞芯微 RV1126B 这类平台对热成像做了原生支持：双路 MIPI-CSI 之外，ISP 里带了 IRFPA（红外焦平面）数据处理——像素偏置校正（OCC）、自动 NUC、去横竖条纹、动态范围压缩这些都是硬件管线，等于把第二步要自己搭的一部分图像算法下放给了芯片，再配 3 TOPS NPU 跑人车分类。全程要惦记三个预算：内存（逐像素温度矩阵和配准表都不小）、算力（640×512@25fps 的管线每秒要过 800 万像素）、带宽（两到三路码流）。

第一步：机芯选型与接口

嵌入式热成像的起点永远是"用哪块机芯"。主流选项按分辨率和集成度排：

模组分辨率像元NETD接口输出适合
Melexis MLX9064032×24热电堆~100mKI2C温度数组MCU 级玩具/占位检测
FLIR Lepton 3.5160×12012μm~50mKVoSPI+CCI（配 PureThermal 转 UVC）RAW14 / radiometric快速原型、学习
艾睿 MicroIII / Tiny1-C256×192~640×51212μm≤40~50mKMIPI / 网口YUV 直出或 RAW正经嵌入式产品
FLIR Boson+320×256~640×51212μm≤30~50mKMIPI / USBYUV / RAW radiometric高端原型、无人机
高芯 / 海康微影机芯至 1280×102412~15μm≤40mK网口 / MIPIYUV + 测温数据项目型整机

第一个分叉是输出形态：机芯内置 ISP 直出 YUV（省事，画质绑定机芯算法，测温数据一般单独走通道），还是吐 RAW14 由你自己建管线（可控，能优化测温与融合，代价是 NUC/AGC 的活全在你）。消费级模组（Tiny1-C 这类）主打前者，工业机芯两种都给。

选型绕不开价格。2026 年项目口径的机芯价格带：256×192 / 384×288 约 ¥1,000–8,000；640×512（12/17μm）约 ¥8,000–40,000，国产白牌出口价能压到 550–680 美元；1024×1280 级 ¥50,000 起步；制冷型 MWIR 从 ¥80,000 到 ¥300,000。几个有公开报价的锚点：亚立光 TypCor-S640（640×512/12μm/≤35mK/50Hz）679 美元起、10 件以上 638 美元；烟台博图 BT-SE 系列（同规格）550 美元起、两件起订；乐科思 FTM640（USB/CVBS 输出、含镜头 <25g）¥4,999。同样写"640×512"，报价差出好几倍的区别在测温标定（带出厂黑体多点标定的贵）、镜头和机芯算法链的完整度——比价时先对齐这三项。

第二个分叉是物理接口：

  • I2C（MLX90640）：MCU 直接读温度数组，8Hz 刷新，没有"图像"可言
  • VoSPI（Lepton）：SPI 上的专有时序协议，逐行撕包，裸接 SoC 的 SPI 调时序很折磨；更省事的路子是配 GroupGets 的 PureThermal 板，固件把它转成标准 UVC 相机，Linux 上就是 /dev/video0
  • MIPI CSI：正经机芯的标准姿势，接 IPC SoC 的第二路 MIPI——注意很多机芯不是标准 sensor 时序，需要在 SoC 侧注册 sensor 驱动（海思 SDK 里要写 sensor 扩展）
  • 网口：重载机芯直接出 RTSP/私有协议，你的 SoC 退化成一个"转发+融合"角色

快速验证建议从 UVC 路线走起：Lepton + PureThermal 插 Linux，v4l2-ctl 抓 raw14 帧，管线调通了再换 MIPI 机芯上真板子。

第二步：图像管线——一套没有 3A 的 ISP

热像管线和可见光 ISP 的骨架完全不同：没有 Bayer 排列所以不需要 demosaic，没有自动曝光/白平衡/3A 这些依赖光照量的环节；取而代之的是热成像特有的 NUC 和 AGC。动画里从上到下就是数据流的顺序。

NUC（非均匀性校正）是热像管线的第一道坎。微测辐射热计每个像素的响应曲线和偏置都不一样，不校正的画面是满屏固定条纹（固定图案噪声，FPN）。工程做法三段：

  1. 出厂均匀面标定，得到一组逐像素增益/偏置系数，存在 flash 里
  2. 运行时靠挡片（机械快门）周期性遮挡镜头，用均匀参考面更新系数——这就是热像仪每隔几十秒"咔"一声的原因
  3. 无挡片（shutterless）方案靠场景运动逐帧估计漂移，省掉机械件但算法难度上去了，艾睿的"无挡片"机芯走的就是这条路

挡片触发的瞬间画面会冻结一帧，编码端要处理：缓存上一帧顶上，或者挡片期间不送编码，否则录像里会有规律性卡顿。

AGC（自动增益）解决的是"14bit 数据怎么显示成 8bit"的问题。热像原始数据动态范围远超 8bit 显示，映射方式直接决定观感：

  • 线性拉伸：最简单，场景温差大时画面一片死白或死黑
  • 直方图均衡：对比度拉满，但把噪声也放大了
  • 平台直方图均衡（plateau histogram equalization，PHE）：给每个灰度 bin 的增强倍数设上限，热像工程的主流选择——对比度和噪声之间的折中

还有一个实践中容易踩的坑：测温模式和观察模式的映射要分开。AGC 是动态的，画面灰度会跳变，直接在 AGC 之后的灰度上叠加温度读数会出现"数值没变颜色变了"的诡异显示。测温叠加要用锁定映射或者直接在温度域伪彩上画。

伪彩就是一个 256 项的 LUT 查表（白热、铁红、彩虹），代价可以忽略。

第三步：测温链路

从"画面亮度"到"能报数的温度"，中间是一条独立的标定链。

原理一句话：像元响应值正比于目标辐射亮度，辐射亮度又是温度的单调函数，所以标定的本质是建一条响应值→温度的反演曲线。厂商做法是出厂对探测器做多点黑体标定（对着一组已知温度的黑体记录响应），拟合成几组标定参数（Lepton 的 radiometry 模型给的是 R/S/B/C/O 一组系数，国内机芯常给温标表），运行时代入响应值反解温度。

标定完的相机拿到现场，测温还要过参数关。辐射传输链路上每一环都影响读数，ONVIF 规范定义的那 8 个参数就是完整的现场账单：

  • 发射率（emissivity）：最大误差源。光亮金属 0.1~0.3，氧化/粗糙表面 0.9+。测不锈钢罐壁不贴黑体胶带，设 0.95 能差出几十度
  • 反射环境温度：目标表面反射的周围环境辐射，测低发射率表面时权重巨大
  • 目标距离：大气吸收与光斑大小都随距离变
  • 大气温度、湿度：8~14μm 的大气透过率修正

工程上的现实预期：实验室黑体（发射率 1.0、充满视场、可控反射环境）能兑现 ±2℃/±2%；现场金属光面、小目标、远距离的误差会比标称大几倍。测温型相机的正确用法是盯趋势和相对变化（这个接头比昨天热了 15℃），而不是当温度计用绝对值。

需要逐像素温度场时（等温线、温度趋势分析），取数方式是整机出"带温度矩阵的抓图"（海康的 JPEG append data，640×512 float 温度阵一帧 1.25MB）或 radiometric JPEG（FLIR），不要试图从视频流里反推——视频流是 AGC 之后的 8bit 灰度，温度信息已经不可逆地丢了。

第四步：双光同步与配准

双光谱相机的两路画面要叠加、融合、联合分析，先得对齐——时间和空间都对齐。

时间同步：两路 sensor 进同一颗 SoC 是最省事的结构，硬件上给两路共时钟（或一路给另一路发帧同步信号），帧级对齐就没有问题。跨设备（机芯和可见光相机分体）就只能靠时间戳，用同一时钟源（PTP 或主从 NTP）把误差压到一帧以内，否则回放和联合分析都会错位。

空间配准：上一篇讲过视差——两镜头基线 B、目标距离 d，错位 Δ = B·f/d，与距离成反比。工程流程：

  1. 工厂用一个已知距离的靶标（点阵/十字），在可见光和热成像画面里各取一组对应点
  2. 拟合单应矩阵（3×3，把热图坐标映射到可见光坐标；分辨率不同没关系，矩阵会处理缩放）
  3. 生成 remap 查找表（两张 640×512 的坐标表），运行时查表重采样

一个现实约束：单应配准只在标定距离附近准确（视差是深度相关的，单应假设是平面场景）。所以厂商会标"最佳配准距离"（比如 50m 或 100m），安防场景目标基本在这个距离之外，残余错位可以接受；如果应用场景深度变化大（近距离机器人），就得做深度自适应配准或者干脆用画中画不融合。

第五步：融合与多路编码

融合的算力谱系从轻到重：

  • Alpha 混合：融合图 = α·热图 + (1-α)·可见光图，一乘一加每像素，NEON 优化后 640×512@25fps 占个位核就够；用 SoC 的硬件 overlay（OSD 图层做半透明混合）连 CPU 都不占
  • 金字塔融合（Laplacian pyramid）：边缘保持明显更好，多尺度分解重建的算力在嵌入式上要精打细算，25fps 实时需要 NPU 或重度 NEON
  • AI 融合（GAN/diffusion 类）：效果最好，目前离嵌入式实时流最远，处于论文和旗舰演示阶段

编码侧的账：可见光 4MP H.265 约 4Mbps；热流 640×512 H.265 约 12Mbps；融合流按热流分辨率再算一份。三路并存约 610Mbps/台，NVR 端存储按这个预算。热流编码有个特性：画面大面积静止（工业场景），码率极低，但挡片触发和 AGC 跳变会造成瞬时报文尖峰——码率控制建议 CBR 上限留余量。

第六步：平台接入

到这一步，你的设备已经出图了，最后是让它"看起来像一台正经相机"。

通道注册：按行业惯例注册两个通道——通道 1 可见光、通道 2 热成像。ONVIF 侧每通道一套 Media profile；GB28181 侧在设备目录里给热成像通道标 PhotoelectricImagingType=2，NVR 平台靠这个字段识别通道类型。

事件上报：测温/火点事件的三条路——ONVIF RadiometryAlarm（走 Profile T 的事件框架）、厂商 SDK 布防回调（HCNetSDK 的 COMM_FIREDETECTION_ALARM）、GB28181 报警（没有火点枚举，只能私有 AlarmType 扩展，跨厂商不通用）。事件里带上规则名、温度值、坐标和热图快照，NVR 端才能联动录像和上墙。

兼容性现实：第三方 NVR（Synology、UniFi、开源 Frigate/ZoneMinder）会把你的设备当两台普通相机，测温规则界面和事件检索都不存在。想让测温能力完整兑现，要么配同厂 NVR，要么自己把事件旁路推到业务系统（MQTT/HTTP webhook 是常见做法）。

第七步：智能分析

上一篇说过分工：检测在前端，聚合在平台。前端要做的就两类：

火点检测。不是"温度高就报警"一句话的事，裸阈值报警一天能误报几十次（行人、车灯、反光全中招）。工程化的判定链是一条流水线：

四道判定各有各的活：阈值筛掉背景（典型阈值 60℃ 起，按场景配）；形态学腐蚀膨胀剔掉单像素噪声、把目标区补实；同一区域连续 N 帧（工程上 3~5 帧）才认，瞬时干扰在这里出局；最后用温升速率区分"真着火"（dT/dt 陡）和"本来就在那的暖源"（暖气片、排气管）。这条链在热流上跑，每帧的算力就是几次阈值扫描加一轮连通域，640×512 上 25fps 用 NEON 很轻松，也可以挪到 SoC 的智能加速模块里。误报源清单（阳光反射的墙面、刚启动的车灯、烟头大小的热源）在验收阶段要逐个过。

周界入侵。热像上直接跑传统背景建模（ViBe、MOG）效果很差——低纹理、低对比度，行人就是一团温度斑。可行做法两条：热通道做温度异常区域检测（人形温度斑 + 尺寸过滤），可见光通道跑正常人车识别，两路结果做联合判决——热报了、可见光也认出人，才联动。这也正是双光谱架构的价值：单热流做识别不靠谱，单可见光夜里是瞎的。

测温精度验收要写清条件（距离、目标尺寸、环境温度、发射率设定），否则"±2℃“在合同里没法对账。

常见的坑

  • 隔着玻璃装热像仪：8~14μm 过不了普通玻璃，室外机箱要留锗窗口。看上去像玻璃的锗片几千块，比整箱别的零件都贵
  • 金属反光当热点：太阳照过的不锈钢面反射环境辐射，读数能到七八十度——是反射不是发热，火点检测的阈值判定要结合区域形状和时域持续性兜底
  • AGC 跳变引发码率尖峰：场景温度突变（开门、人员入画）时 AGC 重新映射，整幅灰度变化让 H.265 瞬时码率翻倍，CBR 上限要留余量
  • 挡片帧混进智能分析：挡片触发的整幅变化会被运动检测当成"全场运动”，分析流水线里要把挡片窗口期旁路掉
  • 双流时间戳漂移：两路各自打时间戳，跑一天漂出几百毫秒，回放联合分析就错位——用同一时钟源，定期对齐
  • 开源 NVR 消费不了热事件：Frigate/ZoneMinder 只有"两路普通视频"，事件要自己旁路推业务系统，别指望它在 NVR 界面里给你画测温规则
  • 锗镜头清洁：不能用普通镜头布硬擦，镀膜和镜片都软，按厂商规程来；划伤是不可修复的
  • 9Hz 出口版当追踪用：出口审查宽松的 ≤9Hz 版机芯便宜好买，但 9Hz 意味着每 110ms 才一帧——巡航速度 15m/s 的无人机每帧间隔移动 1.67 米，低空飞行、云台跟踪这类场景完全不可用。做海外产品要么接受 9Hz 只做静态测温，要么老老实实解决 25/50Hz 标准版的合规
  • 长焦锗镜头比机芯还贵：边境、海事、机场要的长焦/连续变焦红外镜头（锗、硒化锌材料），成本有时不低于机芯本体。询价时确认"机芯 + 镜头 + 结构件 + 标定"的整体交付价，别按模组报价做预算

配套阅读：业界与产品调研见《双光谱热成像摄像机调研：原理、NVR 配套与业界现状》。技术细节可对照 FLIR 的 NUC 说明、ONVIF Thermal Service 规范与所用机芯的 SDK 开发指南。
