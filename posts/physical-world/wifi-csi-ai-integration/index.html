把 AI 接进 CSI 感知栈：接得上的层与接不上的层

September 27, 2026 September 27, 2026 物理世界开发 WiFi 感知, CSI, LLM, 边缘计算, Home Assistant 信号与图像处理系列 5853 字 12 分钟阅读
🔊

两块 ESP32 板、一条限频 50 包的串口流、PC 侧一套感知引擎、Home Assistant 里几个实体——这套 CSI 感知栈在家跑起来之后，下一个绕不开的问题是：AI 接在哪。这个问题容易答成两个极端：一个是把 LLM 当万能插件什么都想接一下，另一个是觉得波形信号处理和语言模型隔行隔山干脆不碰。两个极端都不需要，需要的是把栈按时间常数拆开，逐层看 LLM 的延迟、成本、模态对不对得上。

这篇就是这个拆法：先分层，再逐层说过接不上的是哪几层、为什么，接得上的几层各自干什么活；中间拿一个现成的开源项目逐点对号——RuView 已经把运行期和开发期的安装点全部做成了代码；最后落到开发期一个现在就能用的做法，用合成信号给 AI 写的信号处理代码当地基。

栈的时间常数：第一把尺子

把感知栈从下到上摆开，每一层的时间常数差着量级：

层典型节奏载体
采样与限频每包 20 ms（50 pps）MCU 固件
DSP 判定100 ms ~ 1 s端侧小模型或 PC 引擎
事件判定秒级防抖、迟滞、冷却
规则执行事件驱动平台自动化引擎
归因与报告小时到天目前没人做——LLM 的位置

LLM 一次调用的延迟以秒计，成本按 token 计。拿这两条去对表：实时路径每秒 50 包、每包 16 个复数，喂不进去，也没必要喂——这一层的判定本来就该是毫秒级的数学，不是阅读理解。而"昨天家里的感知为什么抽风"这种问题，节奏是小时和天，正好落在 LLM 的舒适区里。

接不上的两层：实时判定与事件执行

实时判定层。 三个硬约束，一个比一个根本：

  • 延迟。人走动时多普勒能到 16 Hz，判定慢半拍，事件就已经过去了。感知判定给的预算是毫秒到百毫秒，LLM 一次调用秒级起步，中间差着两个数量级。
  • 成本。50 pps 的流一天四百多万包，哪怕每次调用一分钱，一年也是五位数——为一个本该在 240 MHz 单核上跑完的帧间差付 API 账单，账算不过来。
  • 模态。LLM 吃 token。CSI 是复数流，把 I/Q 数组序列化成文本塞进去，等于把一个数值计算问题改写成阅读理解题，中间的序列化既丢精度也丢结构。LLM 对"这段波形长什么样"没有任何直觉，它没见过波形。

端侧这一层的 AI 本来就该是小模型：ESPectre 的高精度检测器是一个 529 参数的神经网络，我的 S3 板上是幅度帧间差加双阈值迟滞。大小模型在这里的分工不是新旧交替，是延迟预算画出来的界。

事件执行层。 防抖、迟滞、冷却是确定性逻辑，行为空间小到可以穷举测试：连续 8 帧超进阈值才报在场、16 帧低于出阈值才报离开，每条边都能手工验证。家庭自动化的底线是可复现——同样的输入要同样的输出，不然你不敢把告警和联动挂在它后面。LLM 的非确定性放进这一层，你得到一个"大多数时候对"的家，而大多数时候对的自动化，比明确不工作的自动化难排查得多。

规则可以让 LLM 生成，执行不过 LLM。生成是一次性的离线动作，执行是每秒都在发生的在线动作，两者对确定性的要求完全不同——这句话是这一整节的结论。

接得上的两层：归因报告与规则生成

归因与报告。 LLM 的正确输入不是波形，是事件流：时间戳、分数、状态变迁，再配上射频侧已知的环境注释——微波炉干扰的频段特征、信道跳变的时间点、路由器夜间自动换信道的时段。判断仍然由规则和统计做，LLM 拿着结论组织成人话：一份日报写"19:40 起客厅节点连续误报十分钟，与厨房微波炉使用时段重合，建议感知信道往 1 侧挪"，比让你自己翻三天日志快得多。价值真实，但别高估：实现就是一个定时任务加一次 API 调用，几十行代码，它省的是翻日志的时间，不是检测器的精度。

自然语言生成规则。 CSI 的事件类型天然就少：在场、运动、离开、静止，撑死了再加一个长时间不动。动作空间小正好是 LLM 生成规则的舒适区——生成的自动化先过一遍 schema 校验再入库，非法结构根本进不了引擎，跑错了也能一眼看出是哪条规则。Home Assistant 已经把 LLM 接进了对话层，剩下的工程是把感知实体和事件语义喂给它，这部分没有技术悬念，只有工作量。

隐私的账。 波形编码的是整个房间的几何——哪里有墙、哪里有人、呼吸的节律都在里面——波形不出户是底线。事件级数据（布尔加时间戳）敏感度低一个量级，数据量小到上云成本可以忽略，取舍在隐私不在钱。想再收紧，报告层可以换本地小模型，代价是归因质量掉一截。波形、事件、报告三层分开，每层各自决定出不出户，比"整个系统上不上云"这种问法有用得多。

身份是单独的一档。RuView 的隐私层做过一个实测：只用 WiFi 的心呼吸通道做两个人的身份匹配，差距只有 0.0005——在它的通道设计里，“认出这是谁"物理上就近乎分不开。于是它把身份识别标成实验能力并加数据门控，想用就得显式开通道。感知和身份在工程上是两件事，分层的时候值得把这一档单独画出来。

现成的参照：RuView 把 AI 接在哪

上面这套分层不是纸面推演。WiFi 感知开源项目 RuView（本系列拆过它的信号管线）把运行期和开发期的 AI 安装点全部做成了代码，三个安装点各对应一节。

训练在设备外，推理在设备上

它的时间常数账和上面算的一模一样。自监督对比编码器的训练发生在服务器：6 万帧 CSI、61 万个对比三元组、1,220 万步训练；落到 ESP32 上的是另一组数——4-bit 量化后 8 KB 的编码器，加每个房间 1,792 参数的 MicroLoRA 适配器，整套约 55 KB，占 520 KB 内存的一成。训练吃小时级算力，推理给毫秒级响应，两头各干各的，中间只隔着一次量化下发。

逐房间 MicroLoRA 值得多看一眼。环境基线随房间和家具漂移，这是 WiFi 感知的公共难题，它的解法是每个房间训一对低秩小矩阵，主干不动——和我在板上做的阈值学习是同一个思想：环境漂移用小参数量的适配去追，只是人家用的是神经网络版。标注问题的解法也在这条线上：对比三元组从时间结构自动构造，零人工标注；要到姿态那一层才需要标签，它用 MediaPipe 从摄像头拿关键点给 CSI 当老师，跨模态微调在 RTX 5080 上 400 个 epoch 只要 2.1 秒（ADR-079）——标签的贵贱，决定了 AI 接进来是顺手还是要命。

动画把这条"训练→量化→下发→逐房适配"的链走了一遍：左边服务器转一整轮，中间紫色块被量化压小，右边设备上只落 55 KB；下面三个房间的橙色适配芯片轮流亮起——每个房间一对 1,792 参数的小矩阵。

MCP：把事件喂给 agent，不喂波形

运行期的接入点，RuView 做的是一个 MCP 服务器（ADR-124）：暴露给 AI agent 的工具一共六个——在场状态、呼吸、心率、体征汇总、最近一次隐私层扫描、事件订阅。这六个工具的返回值值得逐个看：全是结构化状态和数值，没有一个返回原始 CSI。传输配置和前面的隐私账同一思路：默认绑 127.0.0.1、bearer token、Origin 校验、只读。LLM 在这套架构里的输入边界不是靠提示词约束的，是画在 API 上的——它看得见"客厅有人、呼吸每分钟 14 次”，看不见波形长什么样。

这就是"归因报告"一节的工业级版本：把事件流包成只读接口，LLM 拿到什么、拿不到什么，接口说了算。

动画里绿色的事件令牌从节点穿过上方的只读闸门，抵达右边的 LLM；红色的波形令牌撞在下方闸门上弹回节点——六个工具的返回值没有一个是原始 CSI，边界不在提示词里，在这道墙上。

诚实护栏：把"数字要人核"做成工具

开发期的接入点最有意思。这个 README 近万字、9.2 万 star 的仓库，自己承认实机姿态模型 PCK@20 只有 3.0%，推理路径还是返回 confidence=0 的占位实现；为了防止 AI agent（和人类读者）把营销数字当实测数字转述，它做了一层 MetaHarness：agent run 默认只读，写盘需要 --allow-write 和 --confirm 双开关；claim-check 专门检查一份报告里的宣称有没有实测背书——ADR-182 把 MEASURED 和 CLAIMED 的区分做进了代码。背后还有一条证据链兜底：verify.py 确定性重放整条管线并核对 SHA-256，输出 VERDICT: PASS 才算数；测量记录进 Ed25519 witness chain 防篡改；一张 33 行的能力宣称矩阵，逐行挂着证据链接。

上一节说常数要人核，靠的是个人纪律；到了这个规模，纪律长成了工具——宣称没有证据链接就过不了校验。这一手比仓库里任何一个模型都值得抄。

开发期：AI 写代码，人管常数

运行期的分工说完，开发期是另一回事。这套栈的固件、解析器、DSP 代码，本来就是和编码 agent 一起写的，CSI 代码有两个特殊的地方值得单独说。

第一，常数要人来核。 LLM 写解析和滤波代码又快又顺，但常数会幻觉：子载波索引表按芯片和带宽各不相同，HT40 的 128 个子载波映射整个重排过，不是 HT20 的简单拼接——LLM 会顺手把 Intel 5300 的索引表答给 ESP32，采样率也是张口就来。对策朴素：每个常数带出处注释，解析器和串口帧格式当成一对改，改一处必改另一处；最后靠下面这招兜底。

第二，合成信号当 ground truth。 多径模型十几行就能造出带已知运动的合成 CSI：

import numpy as np

n_pkg, n_sc = 600, 16                      # 10 秒 × 50 包，16 个抽取子载波
t = np.arange(n_pkg) / 50.0
base = np.random.randn(n_sc) + 1j * np.random.randn(n_sc)   # 静态多径基线
breath = 0.03 * np.exp(1j * 2 * np.pi * 0.3 * t)            # 0.3 Hz 呼吸：公共相位摆动
walk = np.zeros(n_pkg)
walk[300:360] = 0.4                                         # 第 6 到 7 秒的走动突发
csi = base[None, :] * (1.0 + breath[:, None] + walk[:, None])
csi += 0.02 * (np.random.randn(n_pkg, n_sc) + 1j * np.random.randn(n_pkg, n_sc))

这是玩具级合成：呼吸建成了所有子载波同相的公共摆动，多径的选择性没建——真实的呼吸信号是路径相关的。但拿它测检测器的回归够用了：该报运动的位置报了、该安静的位置安静了，改动就没把逻辑改坏。反过来说，AI 改一版滤波器，跑一遍合成序列立刻知道改坏没有，不用每次上板烧录、盯串口、肉眼对波形。

合成器本身是纯数学，没有硬件依赖，恰好是 AI 写得最可靠的代码。让 AI 写常数之上的数学，人核对常数，这个分工在开发期是成立的。

人的位置。 AI 没有波形直觉。示波器上"这段不对劲"的判断，来自你看过几百段真波形；AI 只能看你写下来的判断。把直觉翻译成断言和统计特征喂回给测试，是开发期协作里人该占的位置——人的注意力花在哪，决定这套协作能转多快，这个话题在循环工程里已经说过，这里不展开。
