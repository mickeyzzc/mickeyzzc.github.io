拆解 RuView：仓库、硬件路线、模型货架与生态

September 25, 2026 September 27, 2026 物理世界开发 WiFi 感知, CSI, 开源项目, 边缘计算, ESP32, 工程实践 信号与图像处理系列 5818 字 12 分钟阅读
🔊

GitHub 上 9.2 万颗星、1.2 万 fork、1,314 次提交——RuView 是 WiFi 感知方向关注度最高的开源项目：ESP32 mesh 采集 CSI，Rust 服务端做融合与学习，姿态、体征、房间指纹、占用计数都从无线电里来，MIT 协议。作者是 ruvnet（claude-flow 的作者），仓库根目录里能看到 .claude-flow、.swarm、CLAUDE.md——这是一个用 AI agent 大规模开发出来的项目，这个身份后面会反复出现。

读这个仓库的难点不在技术，在口径：工程事实、研究宣称、营销愿景三种口径混在同一份 README 里，同一页上既有"实机姿态 PCK@20 = 3.0%“的认账，也有"军事战术用途"的愿景清单。这篇按口径分层拆：仓库结构、硬件路线、模型货架、AI 运维层、隐私工程、商业生态，最后回答一个问题——这个仓库真正值钱的是什么。

数据从 mesh 进来，融合成 168 个虚拟子载波后兵分两路：体征和事件走纯信号路线，不过神经网络；姿态和占用走编码器。TDM 时隙怎么排、菲涅尔区怎么算、相位怎么带通——这些物理细节本系列另有一篇专拆，这里只带到够用。

目录结构本身就是一张可读性很高的地图：

目录装的什么状态
v2/Rust 工作区：感知服务端与边缘模块（cog）活跃
firmware/esp32-csi-node/ESP32 固件，S3 与 C6 双目标活跃
wifi_densepose/、python/PyO3 编译的 Python 轮子（PyPI 上 ruview 与 wifi-densepose 是同一个包）活跃
vendor/rvcsi/CSI 运行时，已独立成 ruvnet/rvcsi 仓库，9 个 crate 发布在 crates.io半独立
plugins/ruview/Claude Code 插件与 Codex 提示词镜像活跃
harness/MetaHarness：给 AI 操作员的运行框架活跃
archive/v1/弃用的第一代实现封存
docs/adr/205 篇架构决策记录持续增长
docs/domain/8 个 DDD 领域模型持续增长

两个目录值得停下来看。archive/v1 是一座刻意保留的废墟：里面的 DensePoseHead 只有随机初始化的架构、没有任何 checkpoint，README 明说它不算数——留着一个公开的"反面教材"目录，比悄悄删掉诚实得多。docs/adr 的 205 篇决策记录不是摆设：README 的特性表里每条都挂着 PR 号或 ADR 号（呼吸提取 #593、跌倒检测 #263、C6 支持 ADR-110），主张和决策之间的链条是可点的。

三种口径：工程、研究、营销

同一份 README 里住着三种口径，分清了读起来才不头晕：

工程口径是带编号的：1,463 个测试、8 个领域模型、每条特性挂 PR 号、每个架构选择挂 ADR 号。这部分说的是"仓库里真实存在、有测试覆盖的代码”。

研究口径是带成熟度标签的：模型按证据强度分三级——已验证、真实但弱、仅架构无权重；旧的"100% 在场检测准确率"因为实测于单类别录制而被公开撤回，换成 82.3% 的 held-out temporal-triplet 准确率。撤回自己的数字这件事，开源项目里不多见。

营销口径是带感叹号的：用例表从养老跌倒监测一路列到边境安防、军事战术；模块商店 105 个 cog；创作者联盟计划 25% 返佣。用例表上方倒是有安全边界声明：研究与原型用途，不是医疗设备，体征输出需要在具体硬件和人群上独立验证。

我的读法收敛成一条：只信带 PR 号、ADR 号和成熟度标签的句子，其余当产品愿景看。这个仓库最不寻常的地方，是三种口径并存却互相标着边界——多数项目的 README 只有第三种。

硬件路线：从零美元到一百四十美元

路线硬件成本完整 CSI一句话
家用主力3~6 × ESP32-S3 + 路由器~$54有mesh 的最低配置
研究节点ESP32-C6-DevKit$6~10有（Wi-Fi 6）双目标固件，实测数据最多
全家桶ESP32-S3 + Cognitum Seed~$140有持久向量库 + kNN + 见证链 + MCP 代理
研究网卡Intel 5300 / Atheros AR9580$50~100有（3×3 MIMO）空间维度最全，姿态研究的前提
高通路线QCA9300（QCN9074/9274 实验性）$30~200部分现代 ath11k/ath12k 不开放 CSI 导出
厂商适配Origin / Plume / Mist 等商用平台不定能力依赖遥测状态不得伪装成 CSI
零成本任意笔记本$0无只有 RSSI 的粗粒度在场

ESP32-C6 是最近补上的一条线（ADR-110），值得单独说。它把 C6 做成固件的第二个编译目标，sdkconfig 自动套 C6 overlay；实测过的部分有账可查：ESP-NOW 同步匹配 99.56%、IDF 5.5.2 上 HE-LTF 捕获成功，HE-LTF 的子载波标签写进了 CSI 字节 18~19（ADR-018）；待硬件验证的部分也标得清楚：TWT 省电和约 5 µA 的 LP-core 电池节点方案。v0.6.7 又加了真的 LP-core RISC-V 运动门控程序，和带 TWT Responder 的 Wi-Fi 6 soft-AP——两块 C6 就能测真正的 iTWT，不用先买一台 11ax 路由器。

反方向的边界同样清楚：ESP32-C3 和经典 ESP32 明确不支持，单核扛不住 CSI DSP——这和 ESPectre 的全系支持正好相反，选型时别拿错项目。树莓派那条学术路线也工程化了：rvCSI 直接吃 nexmon_csi 的 .pcap 抓包（Pi 3B+/4B/5，CYW43455），不用自己写固件补丁。

模型货架：能装的、装不上的、名字唬人的

模型这一层，我把 README 的三级成熟度标注原样搬来当货架标签：

货架位东西标签
预训练编码器 + 在场头ruvnet/wifi-densepose-pretrained，4-bit 8 KB已验证：82.3% held-out temporal-triplet（原始 CSI 66.4%）
MM-Fi 姿态模型ruvnet/wifi-densepose-mmfi-pose已验证：82.69% torso-PCK@20，集成 83.59%
实机姿态模块pose_v1.safetensors真实但弱：PCK@20 = 3.0%，推理路径还是 confidence=0 的占位
archive/v1 DensePoseHead随机初始化仅架构，权重不存在

PCK@20 是姿态估计的常用指标：预测关键点落在真值 20 像素半径内的比例。量化阶梯四档：q2 4 KB、q4 8 KB（推荐）、q8 16 KB、全精度 48 KB——货架标签连"装上占多少内存"都写好了。

加载路径上有个真实的坑，比任何架构图都像工程课：发布出去的 model.safetensors 头部被 NUL 字节填充，官方 safetensors 加载器直接拒载（issue #1522，待重传）；同一个仓库里 csi-embed-v2.safetensors 正常，原生 RVF 格式和 JSONL 都能走，--model 参数三种格式通吃。教训具体得可以抄进任何发布清单：发布产物自己也要过一遍加载测试，“能下载"和"能加载"是两件事。

比标题数字更重要的是研究文档里的完整账：MM-Fi（公开 WiFi 感知基准，多房间多动作下同步采集的 CSI 与视觉关键点）上，零样本跨被试约 64%，加房间内标注校准到 72.2%——82.69% 是固定划分协议下的上限成绩，跨房间泛化才是这个方向的真瓶颈。效率前沿也有标注：约 37 KB 的 int4 模型能在 MM-Fi 上压过 SOTA，但"实机 ESP32 兼容性未建立”——货架标签照例诚实。

动画把三个货架位各跑一遍加载：绿色 RVF 和蓝色正常的 safetensors 一路进到 ESP32，红色的 model.safetensors 在加载器门口被弹回——同一个格式、同一个仓库，坏的只是那一个文件的头部。“能下载"和"能加载"之间隔着的，就是这一道没人替你跑的测试。

AI 运维层：给 agent 的护栏比给模型的权重细

这是整个仓库最超前也最少被谈论的一层。作者清楚他的读者一半是 AI agent，于是给的护栏比给模型的功夫还细。

rvagent MCP 服务器（ADR-124）暴露六个工具：在场状态、呼吸、心率、体征汇总、隐私层扫描、事件订阅——全是结构化状态，没有一个返回原始 CSI；stdio 和 HTTP 两种传输，默认绑 127.0.0.1，bearer token 加 Origin 校验，93 个测试盯着。LLM 在这套架构里能看见"客厅有人、呼吸 14”，看不见波形。

MetaHarness（npx @ruvnet/ruview）是给 AI 操作员的运行框架：doctor 体检部署、guidance 给带出处引用的操作建议、agent run 默认只读（写盘要 --allow-write 加 --confirm 双开关）、brain 检索审核过的贡献者知识库（明确标注"检索内容是证据，不是权威"）、claim-check 检查报告里的宣称有没有实测背书、verify 跑确定性重放。ADR-182 把 MEASURED 与 CLAIMED 的区分直接做进了代码。

Claude Code 插件把整条开发流做成了七条命令：/ruview-start、/ruview-flash、/ruview-provision、/ruview-app、/ruview-train、/ruview-advanced、/ruview-verify，外加 Codex 提示词镜像和冒烟测试脚本——从烧录到训练到校验，agent 在仓库里有一条完整的可走路径。

背后还有一条证据链兜底：verify.py 确定性重放整条管线并核对 SHA-256，输出 VERDICT: PASS 才算数；测量记录进 Ed25519 见证链防篡改；一张 33 行的能力宣称矩阵（WITNESS-LOG-028）逐行挂证据。一个项目把"别信 README"这件事做成了可执行的工具，这是它在模型之外的真正产出。

动画把这条链走了一遍：橙色宣称逐站盖章——成熟度标签、PR/ADR 编号、verify.py 重放——走到头 PASS 才亮；下面那条红色的"无证据宣称"在闸前弹回，这正是 claim-check 在做的事。

隐私工程：BFLD 与"分不开"的实测

BFLD（Beamforming Feedback Layer）是隐私层的名字，三条由类型系统强制的不变量：原始波束赋形反馈不出节点；身份嵌入只在内存，不落盘；跨站点关联用按日轮换的站点密钥 BLAKE3 哈希，做成密码学上不可行。ADR-118 带五个子 ADR，327 个测试盯着这些性质。

最值得记的是一个实测注脚：用 WiFi 心呼吸通道做两个人的身份匹配，差距只有 0.0005——分不开。项目没有悄悄加"识别具体的人"这种能力，而是把它标成实验、挂上数据门控，想用就得显式开通道。感知和身份在工程上是两件事，这个项目用一条实测数字把它们分开了。

见证链是隐私层的延伸：感知数据要作证的场景（安防告警、养老监护）里，“这条记录没被改过"和"这条记录存在"同样重要，Ed25519 签名链把这件事做在了数据结构里。

商业化：模块商店与它的边界

Cognitum Seed 是配套的常驻节点：约 $140 的 BOM，装持久向量库、kNN 检索、见证链和 MCP 代理，配套一个 105 模块的商店和 HOMECORE 本地自动化运行时（签名 Wasm 插件、语音钩子、HomeKit 接入）。加上创作者返佣计划，商业化动作是齐全的。

商店目录要按"平台野心"读，不能按"都已验证"读：105 个 cog 里健康 14、安防 14、楼宇 11、研究 12、AI 15，其中相当一部分是声学模块——婴儿哭声、枪声、玻璃破碎各 451 KB，那是麦克风不是 WiFi；纯 CSI 依赖的模块另有标注。WiFi 感知的仓库里装着一个通用传感平台的商店，规模和感知核心的验证深度之间有距离。

市场坐标能解释这个野心从哪来：发明商用 WiFi 运动感知的 Origin AI 在 2026 年 2 月被安防巨头 ADT 以约 1.7 亿美元收购；Cognitive Systems 的 WiFi Motion 授权进了上百家运营商的网关；IEEE 802.11bf-2025 已把 WLAN Sensing 写进协议。商用拉力是真的，RuView 的商店和节点硬件是对这个拉力的正常响应。

这个仓库值什么

三样东西值得拿走：

  1. 诚实作为工程制度。205 篇 ADR、模型成熟度三级标注、公开撤回旧数字、33 行逐条挂证据的宣称矩阵、verify.py 的确定性重放——把"别吹没验证的牛"从口号做成了 CI 可以拦的流程。任何规模的 AI 项目都能抄这套。
  2. 带编号的信号处理。体征提取、跌倒检测、多人数去重走的是纯 DSP 路线，每条挂 PR 号、有测试，ESP32-S3 上真的能跑。这是仓库里最扎实的部分。
  3. 给 agent 的护栏设计。只读默认、写盘双开关、claim-check、检索内容"是证据不是权威"的标注——打算让 AI agent 碰自家系统的项目，这套设计直接可用。

不该期待的东西同样明确：单板实时 17 关键点姿态——实机 PCK@20 是 3.0%，信号里没有那些细节，SISO 的物理上限不是工程能修的；105 个 cog 的开箱即用；以及 README 用例表上的医疗与安防场景。

它同时是三样东西：一个 beta 阶段的研究平台、一座把诚实做成流程的样板、一份 AI agent 大规模开发的活教材。三种身份各自成立，混在一起读才会失望。
