视频监控协议全景：从接入到合规的四层版图，每个协议是什么、管什么、什么时候用

上一篇把 ONVIF 和 GB/T 28181 拆到了信令和报文级别，但真做 NVR 会发现协议环境远不止这两个：摄像头侧有厂商私有 API，公安侧有视图库标准，车载有交通部标准，浏览器观看有 WebRTC，公网分发有 HLS，安全合规有国密体系。这篇把整个视频监控的协议版图铺开——每个协议按「是什么 → 技术要点 → 和其他协议的关系 → 对 NVR 的价值」四段展开，新手可以当索引读，老手可以直接跳取舍表。

先给一张总图，后面按层逐个展开。

四层各管一件事，理解任何一个「监控协议」前先问它属于哪层——很多协议争论其实是把不同层的协议放在一起比。ONVIF 和 GB28181 是这张图的主轴，其余协议都围绕自己的位置展开。

接入 / 互操作层

这一层解决「NVR 怎么操作摄像头」。理想状态是所有品牌说同一种话，现实是标准与私有 API 并存。

ONVIF：事实上的国际标准

上一篇完整拆过它的机制（WS-Discovery 发现 → SOAP 信令 → RTSP 取流），这里补版图视角的定位：ONVIF 论坛 2008 年由 Axis、Bosch、Sony 创立，现在成员超过 500 家，认证产品超过 33,000 台——渗透率深到「支持 ONVIF」在选型时是默认预期而不是加分项。海康、大华这些有自己私有 API 的厂商，出口和第三方对接也绕不开它。

PSIA：标准战争的败方

  • 是什么：Physical Security Interoperability Alliance，ONVIF 唯一成气候的竞争对手，2008 年初由 Axis、Cisco、GE Security、IBM、Panasonic、Pelco、Sony 等发起（Bosch 站队了 ONVIF）。
  • 技术要点：走 REST 路线，HTTP + XML，接口比 SOAP 简洁；覆盖视频和门禁；设备搜索灵活但厂商兼容性参差；没有强制认证体系。
  • 关系：视频监控标准战争的败方。REST 明明比 SOAP 好用，但 ONVIF 靠创始巨头背书加上可测试的认证体系赢了——「能进认证实验室测一把」的确定性压倒了接口美学。
  • NVR 价值：无需支持。它留下的启示比协议本身值钱：选协议生态时，治理和认证比技术风格重要。PSIA 今天只剩门禁凭证互操作（PLAI、PKOC）还在活动。

海康 ISAPI / 大华 HTTP API：厂商私有但绕不开

  • 是什么：海康的私有 HTTP 接口（ISAPI，Internet Server Application Programming Interface），REST 风格的 HTTP + XML；大华有类似的 HTTP API 体系。
  • 技术要点：接口路径规则清晰，如 GET /ISAPI/Streaming/channels/101/（101=通道 1 主码流）；RTSP 地址可按规则构造：rtsp://ip:554/Streaming/Channels/101（102=子码流）；除取流外还能操作 ONVIF 覆盖不到的海康特色——报警布防、智能分析参数、人脸参数配置。
  • 关系：与 ONVIF 互补：ONVIF 是通用层，ISAPI 是厂商增强层。几乎所有海康设备两者都支持，同一个功能往往两条路都能到。
  • NVR 价值：通用 NVR 优先走 ONVIF；要做海康深度集成（如精细的报警联动、智能配置）必须 ISAPI。架构上预留「厂商适配层」，别把私有 API 调用散落在业务代码里。

联网 / 信令与数据层

这一层解决「系统之间怎么互联」。GB28181 管视频流联网，GA/T 1400 管结构化数据联网，JT/T 808 管车载——三个体系互不相干，各自成套。

GB/T 28181：国内联网的国标主干

机制在上一篇拆透了（SIP 注册 + INVITE 点播 + RTP/PS 推流），版图定位一句话：国内跨区域视频联网的强制基础规范——政府、公安、国企、金融项目基本都要求支持 GB28181 才能接入。它和 ONVIF 不是竞争而是上下游：摄像头 ONVIF 进 NVR、NVR GB28181 上平台。

GA/T 1400：GB28181 的「数据面」（视图库）

  • 是什么：公安视频图像信息数据库标准，俗称「视图库」。如果说 GB28181 管视频流的联网，GA/T 1400 管结构化数据的联网。
  • 技术要点：管理四大类对象——人员/人脸、机动车/非机动车、物品、场景与图像标签；每条「视图」是图片或视频与结构化元数据的捆绑（一张人脸图 + 抓拍时间地点 + 属性描述）。接口分三大类：采集接口（设备/平台向视图库上报数据）、数据服务接口（查询、订阅通知、布控告警）、级联接口（上下级视图库同步）。
  • 关系：与 GB28181 互为「视频面 + 数据面」：28181 把流拉过来，1400 把分析结果存起来共享。国际对标是 ONVIF Profile M（AI 元数据与事件标准接口）——一个是国内公安版，一个是国际版。
  • NVR 价值：做 AI 增值（人脸/车牌检测）并对接公安系统时必用；家用和普通商用可以完全忽略。

JT/T 808 / 1076 / 1078：交通部车载体系

  • 是什么：交通运输部的车载标准族：808 是北斗/GPS 终端与平台通讯，1076 是终端技术要求，1078 是车载音视频通讯。
  • 技术要点：808 基于 TCP 长连接 + 二进制消息（消息头 + 消息体 + 校验码），与 SIP/RTSP 这类文本协议完全是两个世界；1078 扩展实时视频、回放、抓拍；新版本支持主动安全报警（ADAS 高级驾驶辅助、DSM 驾驶员状态监测）。
  • 关系：与 ONVIF/GB28181 无直接关系，车载领域自成一系。
  • NVR 价值：车载 NVR、执法记录仪、「两客一危」车辆监管项目必用；固定安防产品线碰不到。

媒体传输层

这一层解决「流怎么传」。RTSP/RTP 是监控的入口标准，WebRTC 是浏览器实时观看的现答案，RTMP/FLV/HLS 面向分发，SRT 面向弱网。各协议的深度内部机制（拥塞、打包、CDN 适配）在流媒体协议全景里做过 14 种协议的完整对比，这里聚焦它们在监控场景的角色。

一条流进来，出流可以同时走多条路：实时值守用 WebRTC，网页直播用 FLV，手机回看用 HLS。这是现代 NVR 的标准形态——入口单一（RTSP/ONVIF），出口多协议。

RTSP / RTP / RTCP：NVR 的生命线

  • 是什么：RTSP 是「流媒体的遥控器」——只发控制命令不传数据，数据由 RTP 承载，RTCP 负责统计与同步。
  • 技术要点：会话四步 DESCRIBE → SETUP → PLAY → TEARDOWN；H.264 over RTP 按 RFC 6184 打包，大帧拆成 FU-A 分片；RTSP over TCP 用 interleaved 模式（RTP 装进 RTSP 连接里，穿防火墙友好）； RTP 头里的时间戳和序列号是组帧和丢包检测的依据。
  • 关系：ONVIF 取流的最终承载——GetStreamUri 返回的就是 RTSP URL。GB28181 不用 RTSP（它直接 RTP/PS 推流）。
  • NVR 价值：最高优先级，入口出口都要用。几乎所有 IP 摄像头都支持 RTSP，包括不支持 ONVIF 的白牌设备——RTSP 地址几乎是摄像头的世界语。Go 参考实现 gortsplib，Rust 参考 retina。

WebRTC：现代 NVR 出流首选

  • 是什么：浏览器原生的实时音视频标准，亚秒级延迟、免插件、端到端加密。
  • 技术要点：连接建立走 SDP Offer/Answer 交换（服务端封装成 WHIP/WHEP 标准接口）；媒体走 SRTP，密钥由 DTLS 协商；NAT 穿透靠 ICE/STUN/TURN 打洞中继；编解码支持 VP8/VP9/H.264/AV1。
  • 关系：ONVIF 新 Profile V（云/VSaaS）用 WebRTC 做媒体上行；ZLMediaKit/SRS/MediaMTX 都已支持 GB28181 → WebRTC 的直接转换——国标进、浏览器出，中间不用 RTMP 中转。
  • NVR 价值：强烈推荐。监控值守场景对延迟最敏感（事件发生了要立刻看到），WebRTC 是目前浏览器端唯一能做到亚秒级的成熟方案。Go 用 pion/webrtc，Rust 用 str0m / webrtc-rs。

RTMP / HTTP-FLV：直播分发主力

  • 是什么：RTMP 是 Adobe 时代的直播推流协议，Flash 已死但推流至今是事实标准；HTTP-FLV 是把 FLV 容器装进 HTTP 长连接的变体。
  • 技术要点：RTMP 基于 TCP + AMF 消息，延迟 3–5 秒；HTTP-FLV 延迟 1–3 秒，可过 CDN，国内直播平台和微信生态常用。
  • 关系：与 ONVIF/GB28181 无直接关系，但它是国标平台的常见出口：GB28181 接入 → 服务器转 FLV → 网页播放。
  • NVR 价值：需要对接直播平台或兼容老播放器时用；纯低延迟场景被 WebRTC 替代。RTMP 推流对接国内直播平台的实操写过一篇：gortmplib vs go2rtc vs FFmpeg。

HLS：兼容性保底

  • 是什么：把视频切成小片（ts/fMP4）加一份 m3u8 播放列表，纯 HTTP 分发，任何平台都能播。
  • 技术要点：标准 HLS 延迟 6–30 秒（切片时长 × 3 以上）；LL-HLS 压到 2–3 秒；对录像回放特别友好——回放本来就是点播，切片即回放。
  • 关系：与实时协议互补而非竞争；MiBeeNvr 的 HLS 直播与录像回放就是同一条管线。
  • NVR 价值：公网分享、手机观看、录像回放的兜底方案。延迟要求一高就换 WebRTC/FLV。

SRT：公网弱网利器

  • 是什么：Haivision 开源、基于 UDP 的可靠传输协议，专为公网不稳定链路设计。
  • 技术要点：ARQ 自动重传 + 前向纠错（FEC）；AES 加密；原生 NAT 穿越；延迟可配置（重传窗口换延迟）。
  • 关系：与 RTMP 竞争「贡献层第一跳」：跨公网回传时 SRT 的抗丢包远好于 RTMP over TCP。
  • NVR 价值：跨公网取流/回传场景强烈推荐——比如分店摄像头回传总部、工地回传云平台。MediaMTX/SRS 原生支持，Go 生态有 datarhei/gosrt。

编码与安全层

这一层是合规重心，国内项目分三块：

SVAC：国产安防编码

  • 是什么：中国自主的安防视频编码标准，GB/T 25724-2017（即 SVAC 2.0），专为安防监控的痛点设计。
  • 技术要点：三件事是 H.264/265 做不到的——① 信源加密（编解码时国密加密）；② 视频签名（逐帧签名防篡改，证据可采信）；③ 结构化数据内嵌（目标检测结果直接写进码流，解码即得元数据）。GB 37300-2018 要求重点区域采集设备符合 SVAC。
  • NVR 价值：涉密/重点区域项目需支持；普通商用可不做。

GB 35114：国密三级安全

  • 是什么：我国首个视频监控联网信息安全的强制性国标（2017-11-01 发布，2018-11-01 实施），《公共安全视频监控联网信息安全技术要求》。
  • 技术要点：A/B/C 三级递进——A 级：SM2 数字证书双向身份认证（防设备私接乱接）；B 级：A + SM3 逐帧签名（录像作为证据时可验证完整性）；C 级：B + SM4 视频流实时加密（传输防窃听）。配套 PKI 证书体系。GB/T 28181-2022 的新「高安全级别」直接对接它。
  • NVR 价值：涉政企强制。需要国密算法库（SM2/SM3/SM4）和证书管理，选型时提前确认信令栈支持。

等保 2.0 与数据合规

  • 是什么：网络安全等级保护 2.0（GB/T 22239-2019）的物联网扩展要求，加上《网络安全法》《反恐怖主义法》的行业规定。
  • 技术要点：人脸、车牌等数据要分类分级；敏感数据 SM4 加密传输与存储；密钥分级管理；日志留存不少于六个月（网安法第 21 条）、重点目标视频不少于九十天（反恐法第 32 条）；过期数据不可恢复地销毁。
  • NVR 价值：企业级项目需要配套加密存储、审计日志、分级权限、数据销毁能力。提前在架构里留「能力位」比验收前补课便宜得多。

ONVIF 体系 2025-2026 动态

写接入代码前值得花十分钟了解 ONVIF 体系正在发生的变化，好几项直接影响选型：

动态内容影响
Profile S 停发2025-10-09 公告：2027-03-31 后不再接受 Profile S 新认证，原因是 username-token 认证不符合现代安全建议新项目按 Profile T 设计
Profile T 成基线支持 H.264/H.265、元数据流、HTTPS 媒体流官方推荐的 S 继任者
Profile Q 已废弃2021-07 公告、2022-04 生效，安全原因不要再依赖 Q 的快速发现特性
Profile V 进 RC云/VSaaS 场景：WSS 上行 + WebRTC 媒体 + OAuth 2.0（Security Add-on），2026-07 发布 RC，预计年底定稿云端摄像头接入值得关注

NVR 协议取舍表

把版图收敛成一张优先级表（以通用 NVR / 家用和小型商用为主视角，附上为什么）：

协议在 NVR 中的角色优先级理由
ONVIF（按 Profile T 设计）多品牌接入、发现、PTZ必做没有它每接一个品牌就要适配一次
RTSP / RTP入口拉流 + 出口出流必做摄像头世界语，含白牌设备
WebRTC浏览器零插件实时观看强烈推荐值守场景延迟敏感，唯一亚秒级浏览器方案
GB/T 28181国内平台联网、监管对接国内商用推荐做对接政企市场的门票；纯海外可后置
RTMP / HTTP-FLV直播分发、兼容播放按需对接直播平台时才需要
HLS公网分享、录像回放按需兼容性兜底，回放复用
SRT跨公网/弱网取流回传可选加分项多站点组网时价值大
ISAPI / 厂商私有特定厂商深度集成预留适配层深度功能（报警联动、智能配置）只有私有 API 有
GA/T 1400人脸/车牌上报公安涉公安赛道才做数据面对接，工作量不小
