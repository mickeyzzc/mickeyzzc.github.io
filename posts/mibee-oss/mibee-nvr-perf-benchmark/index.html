MiBeeNvr v0.13.0 性能自测：三档硬件的容量与资源曲线

September 24, 2026 September 24, 2026 MiBeeOSS NVR, 性能测试, 流媒体, RTSP, LL-HLS, 存储, 开源 MiBee 开源项目实践系列 7248 字 15 分钟阅读
🔊

NVR 软件选型有一个共同的困扰：找不到带测量条件的公开性能数据。跨产品的第三方压测不存在；能查到的要么是官方自述的局部指标（比如 detector 推理耗时），要么是不标注硬件、码率、帧率条件的编辑估算表，数字之间没法相互比较。

所以这次把 MiBeeNvr 自己的容量与资源曲线测了出来：三种硬件档位，从 16 路到 68 路的录制阶梯、满负载之上的并发观看、纯转发、刷盘策略对照，外加一台 7×24 生产机的只读观察。测量方法、判定口径、测试脚本随文公开。目标不是与其它产品比高低——没有可比较的公开口径，比了也没有意义——而是回答两个选型时真实会遇到的问题：一台给定档位的机器能带多少路；瓶颈出现在 CPU、内存还是存储。

先说结论，数据和工具在后文：

  • 高配 x86：64×1080p + 4×4K 录制，整机 CPU 24%（16 线程口径），NVR 进程内存 171 MB，API p50 全程十几毫秒；之上叠加 32 路并发观看（FLV / LL-HLS / RTSP）零失败。这一档止步 68 路是流量生成端到了上限，不是 NVR 侧出了问题。
  • 入门 ARM NAS（RK3399 + eMMC 级存储）：CPU 只用两成，瓶颈完全在存储——卷设备饱和后 health 接口退化到 2 秒，但录像、逐路口径、录像查询不受影响。切到纯转发 30 路直播，CPU 三成、API 分布完全干净，当直播网关余量充足。
  • ARM 单板生产机（Banana Pi M5）：18 路真实相机 7×24 运行，磁盘 80% IO 等待的压力窗里 API p50 仍 13.5 ms，与 eMMC 档饱和时的 2 秒差两个数量级——存储介质决定低配档的体验上限，这个结论在生产环境得到了复现。

这些数字是厂商自测，这一点不回避：每个数字的测量条件都在文中，工具和口径公开，想核对的话照着跑一遍就行。

两处环境细节值得先交代。RK3399 NAS 的存储卷是 eMMC 分区上的单成员 RAID1 加精简配置卷，写入放大 2 倍——这个细节在后文数据里反复出现，是理解该档位结果的钥匙。生产机在观察窗口内恰逢一次历史录像归档迁移，因此拿到了同一台设备的「高 IO 压力」与「常态」两个观察窗。

受测版本是统一构建的 v0.13.0 预览版；生产观察机跑的是同期预览系构建。

口径：怎么测、怎么算数

负载与测量四件套：

  • 合成摄像头：预渲染 MP4 按 -re 实时 pacing 经 RTMP 接入推流，两种规格——1080p25 H.264 2.5 Mbps（GOP 2 秒、无 B 帧）与 4K25 H.264 16 Mbps。推流端带断线重连，行为对齐真实摄像头。逐路口径靠 NVR /api/streams 计数器周期快照，核对每路入口码率。
  • 资源采样：Linux 端 5 秒间隔读 /proc/stat 原始计数器（可把 IO 等待单列）、/proc/meminfo、NVR 进程 RSS；Windows 端同节奏读性能计数器。磁盘实测以 iostat 为准。
  • API 探针：5 秒间隔请求 /api/health（无鉴权轻路径）与 /api/recordings?limit=5（鉴权 + SQLite 查询路径），记录完整延迟分布与失败数。
  • 观看端：FLV / LL-HLS / RTSP 三协议真实拉流客户端并发观看，统计吞吐、首字节、直播边缘时延（LL-HLS 按 playlist 的 PROGRAM-DATE-TIME 计算）。

判定口径：CPU 占用含软中断，IO 等待单列；「稳态窗口」指最后一台推流器启动 60～75 秒后开始的 4 分钟；表格内 API 延迟取稳态窗口分位数。所有曲线都有逐 5 秒原始数据支撑。

配置口径：除刷盘策略对照一节外，全部测试使用出厂默认——storage.durability 默认 strict 档（每段录像 finalize 时 fsync）、io.budget_bytes_per_sec 默认 0（后台 IO 预算关闭）、预分配开启。也就是说主体数据是默认姿态下的实测，没有借助需要手动打开的优化开关修饰数字。

负载换算：按社区容量规划惯用的 MP/s 量纲折算，1080p25 = 51.8 MP/s/路，4K25 = 207.4 MP/s/路。本次 x86 峰值 68 路约 4,145 MP/s，RK3399 纯转发 30 路约 1,555 MP/s。注意 MiBeeNvr 录制是压缩域直存、不解码，这里的 MP/s 表示吞吐量纲，可与通用方法对照，不能直接等同于解码型负载。

这套口径对应的工具脚本全部收在文末附录。

CPU 曲线在 20～23% 处走平，NVR 进程单核峰值 41.8%。饱和点在存储：iostat 显示卷设备利用率 100%、写等待 3.4～6.9 秒、实际写入约 6～7 MB/s（含 RAID1 写放大）。饱和后的行为是分层的：

  • 录像与逐路口径不受影响——每路码率保持、分段照常落盘；
  • 录像查询（SQLite 读路径）不受影响，p50 全程 20～22 ms；
  • health 检查退化到 2 秒——它内部有一次面向存储卷的 statfs，设备饱和时被阻塞，反而成了「存储在喘气」的信号灯；
  • 极端饱和下的观看：LL-HLS 8/8 客户端拿到数据但起播最长 88 秒、直播边缘 35～53 秒；RTSP 正常出流；FLV 新会话 15 秒内无法建立（健康态实测 106～135 ms）。

负载撤除后恢复很快：health p50 在一分钟内回到 17～23 ms，但背景 IO 使个别请求仍达 2 秒约 6 分钟，之后 max < 31 ms。全程无崩溃、无进程重启。

刷盘策略对照：strict 与 relaxed

durability 决定裸段录像的 fsync 策略：默认 strict 每段 finalize 都 fsync；relaxed 跳过主动 fsync，交给文件系统提交间隔（断电可能丢最后几秒裸段录像，合并/延时产物不受影响）。为量化这个开关在慢存储上的实际收益，做了同负载、同背景（滚动合并后台任务均在运行）的配对测试：

档位durabilityhealth p50 / p95IO 等待CPUNVR 内存
16×1080p（40 Mbps）strict2024 / 3045 ms72.5%20.0%162 MB
16×1080p（40 Mbps）relaxed2019 / 2027 ms73.2%21.1%171 MB
24×1080p（60 Mbps）strict（首轮）2022 / 2033 ms72.0%22.6%203 MB
24×1080p（60 Mbps）strict（配对复测）2020 / 2035 ms68.4%24.9%217 MB
24×1080p（60 Mbps）relaxed2023 / 2040 ms54.7%31.7%131 MB

写路径的瞬时指标确有改善：strict 稳态下卷设备写等待 3.4～3.9 秒、利用率持续 100%；切 relaxed 后写等待降到 0.2～0.3 秒，设备利用率从「持续饱和」变成「突发型」。但从整窗统计看，health 延迟与饱和阈值没有变化——这台 NAS 的存储压力是多个来源叠加的（单成员 RAID1 的 2 倍写放大、滚动合并的后台批量 IO、系统自身的后台读），去掉录像 fsync 只是把持续压力改成了突发压力，不足以把设备拉回非饱和区。

结论：eMMC 级慢存储上，relaxed 能让写排队更平滑，对掉电可容忍的部署是个合理选项，但改变不了这类存储的容量上限；NVMe 等快存储上默认档位本就不构成瓶颈，无需打开。本节也说明主体数据都在默认 strict 档下测得，没有靠这个开关修饰数字。

附注：对照实验期间该容器的一次 docker restart 遇到运行时僵死（docker ps 报 Up 而进程已不存在，stop/start 后恢复；退出前日志无 panic、内核无 OOM 记录，属宿主环境事件而非 NVR 崩溃），SQLite 未检查点的推流键因此丢失（相机与录像数据完好），重建后继续。生产部署建议用 systemd 或应用市场这类正常方式重启，不走 docker restart。

边界与复现

未覆盖项：软件转码规模（H.265→H.264 软转码是 CPU 密集路径，生产建议以子码流直录规避）、WebRTC 端到端时延（依赖浏览器端测量）、万兆网络、云归档吞吐、音频轨、io.budget_bytes_per_sec 后台 IO 预算（默认关闭；测试窗口内后台合并负载固定存在，未单独做 A/B）。合成流为纯视频。

复现：工具就是文末附录里的那些脚本——合成相机源、推流器集群、资源采样器、API 探针、逐路快照、三协议拉流客户端、阶梯编排，配上环境变量即可对任意目标机跑同一场测试。同一硬件上跨产品对照（比如与 Frigate、ZoneMinder 同机同负载）目前同样没有第三方公开数据，属于值得补的对照项，但得先有人把各家软件放到同一套口径里。

仓库：Mi-Bee-Studio/MiBeeNvr。

单路推流器是个断线重连循环——真实摄像头断网后会自己重推，负载模型里不能少这一笔；集群脚本负责批量启停和计数：

#!/bin/bash
# pusher-loop.sh — 单路推流器：断线 2 秒后重连，行为对齐真实摄像头
# 用法: pusher-loop.sh <rtmp基址> <媒体文件> <流名>
BASE=$1; FILE=$2; KEY=$3
while true; do
  ffmpeg -loglevel error -re -i "$FILE" -c copy -f flv "$BASE/$KEY" >> "pusher_${KEY}.log" 2>&1
  sleep 2
done

#!/bin/bash
# pushers.sh — 推流器集群：start <rtmp基址> <文件> <流名...> | stop | count
MODE=$1; PIDF=pushers.pid
case $MODE in
start)
  BASE=$2; FILE=$3; shift 3
  for KEY in "$@"; do
    nohup bash pusher-loop.sh "$BASE" "$FILE" "$KEY" >/dev/null 2>&1 &
    echo $! >> "$PIDF"
    sleep 0.4            # 逐路错开，避免同一瞬间建连风暴
  done
  echo "started=$#";;
stop)
  pkill -f pusher-loop.sh 2>/dev/null
  [ -f "$PIDF" ] && { kill $(cat "$PIDF") 2>/dev/null; rm -f "$PIDF"; }
  sleep 1
  pkill -9 -f 'rtmp://.*/live/' 2>/dev/null   # 兜底清残留 ffmpeg；机器上有无关 ffmpeg 时勿用
  echo stopped;;
count)
  pgrep -fc 'rtmp://.*/live/' || echo 0;;
esac

while true; do
  sleep "$INT"
  C=$(awk '/^cpu /{print $2","$3","$4","$5","$6","$7","$8","$9}' /proc/stat)
  MA=$(awk '/MemAvailable/{print $2}' /proc/meminfo)
  PID=$(pgrep -x "$PROC" | head -1)
  [ -z "$PID" ] && PID=$(pgrep -f "$PROC" | head -1)
  RSS=$(awk '/VmRSS/{print $2}' "/proc/$PID/status" 2>/dev/null)
  PG=$(awk '/pgpgout/{print $2}' /proc/vmstat)
  echo "$(date +%s),$C,$MA,${RSS:--1},$PG" >> "$OUT"
done

"""apiprobe.py — API 延迟探针
用法: NVR_API=http://<host>:<port> NVR_USER=... NVR_PASS=... python3 apiprobe.py <out.csv> [间隔秒]"""
import os, sys, time, base64, urllib.request

base = os.environ["NVR_API"].rstrip("/")
basic = base64.b64encode(f'{os.environ.get("NVR_USER", "")}:{os.environ.get("NVR_PASS", "")}'.encode()).decode()

def timed_get(path, auth):
    req = urllib.request.Request(base + path)
    if auth:
        req.add_header("Authorization", "Basic " + basic)
    t0 = time.perf_counter()
    try:
        with urllib.request.urlopen(req, timeout=10) as r:
            r.read(4096)
            code = r.status
    except Exception as e:
        code = getattr(e, "code", -1)
    return (time.perf_counter() - t0) * 1000, code

f = open(out, "a", buffering=1)
f.write("ts,health_ms,health_code,rec_ms,rec_code\n")
while True:
    ts = int(time.time())
    h = timed_get("/api/health", False)
    r = timed_get("/api/recordings?limit=5", True)
    f.write(f"{ts},{h[0]:.1f},{h[1]},{r[0]:.1f},{r[1]}\n")
    time.sleep(interval)

#!/usr/bin/env python3
"""flvpull.py — FLV 拉流客户端：记录首字节、吞吐、状态码
用法: python3 flvpull.py <stream.flv 的 URL> <out.csv> <时长秒>"""
import sys, time, urllib.request

url, out, dur = sys.argv[1], sys.argv[2], float(sys.argv[3])
t0 = time.perf_counter()
n, ttfb, code = 0, None, 200
try:
    with urllib.request.urlopen(url, timeout=15) as r:
        code = r.status
        while time.perf_counter() - t0 < dur:
            b = r.read(65536)
            if not b:
                break
            if ttfb is None:
                ttfb = (time.perf_counter() - t0) * 1000
            n += len(b)
except Exception as e:
    code = getattr(e, "code", -1)
el = time.perf_counter() - t0
mbps = n * 8 / el / 1e6 if el > 0 else 0
with open(out, "a") as f:
    f.write(f'{url.split("?")[0]},{ttfb if ttfb is not None else -1:.0f},{n},{el:.1f},{mbps:.2f},{code}\n')
print(f"flv code={code} bytes={n} ttfb={ttfb and round(ttfb)} mbps={mbps:.2f}")

#!/usr/bin/env python3
"""hlspull.py — HLS/LL-HLS 拉流客户端：起播时间、吞吐、直播边缘时延（PDT 口径）
用法: python3 hlspull.py <index.m3u8 的 URL> <out.csv> <时长秒>"""
import sys, time, re, urllib.request
from datetime import datetime, timezone

base, out, dur = sys.argv[1], sys.argv[2], float(sys.argv[3])
t0 = time.perf_counter()
seen = set()
n = 0
startup = None
lags = []
pdt_re = re.compile(r"^#EXT-X-PROGRAM-DATE-TIME:(.+)$", re.M)
var_re = re.compile(r"^#EXT-X-STREAM-INF:", re.M)
url = base
while time.perf_counter() - t0 < dur:
    try:
        with urllib.request.urlopen(url, timeout=5) as r:
            txt = r.read().decode()
        if startup is None:
            startup = (time.perf_counter() - t0) * 1000
        if var_re.search(txt):          # master playlist → 跟到 variant
            lines = txt.splitlines()
            for i, ln in enumerate(lines):
                if ln.startswith("#EXT-X-STREAM-INF"):
                    q = "?" + url.split("?", 1)[1] if "?" in url else ""
                    url = url.rsplit("/", 1)[0] + "/" + lines[i + 1].split("?")[0] + q
                    break
            continue
        m = pdt_re.search(txt)          # 直播边缘时延 = 本机时钟 - PDT
        if m:
            try:
                pdt = datetime.fromisoformat(m.group(1).replace("Z", "+00:00"))
                lag = (datetime.now(timezone.utc) - pdt).total_seconds()
                if -5 < lag < 120:
                    lags.append(lag * 1000)
            except Exception:
                pass
        for ln in txt.splitlines():
            if ln and not ln.startswith("#"):
                s = ln.split("?")[0]
                if s not in seen:
                    seen.add(s)
                    u = url.rsplit("/", 1)[0] + "/" + ln
                    try:
                        with urllib.request.urlopen(u, timeout=10) as r2:
                            n += len(r2.read())
                    except Exception:
                        pass
    except Exception:
        pass
    time.sleep(0.4)
el = time.perf_counter() - t0
mbps = n * 8 / el / 1e6
lag_avg = sum(lags) / len(lags) if lags else -1
with open(out, "a") as f:
    f.write(f'{base.split("?")[0]},{startup if startup is not None else -1:.0f},{n},{len(seen)},{mbps:.2f},{lag_avg:.0f}\n')
print(f"hls segs={len(seen)} bytes={n} startup={startup and round(startup)} mbps={mbps:.2f} live_lag_avg_ms={lag_avg:.0f}")

#!/bin/bash
# ramp.sh — 录制阶梯编排
# 用法: NVR_API=http://<host>:<port> RTMP=rtmp://<host>:1935/live \
#       NVR_USER=... NVR_PASS=... bash ramp.sh
set -e
: "${NVR_API:?} ${RTMP:?} ${NVR_USER:?} ${NVR_PASS:?}"
TIERS=("cam1080.mp4:16" "cam1080.mp4:16" "cam1080.mp4:16" "cam4k.mp4:4")
M=marks.txt
mark() { echo "$1 $(date +%s)" >> "$M"; }
snap() { curl -s -m 30 -u "$NVR_USER:$NVR_PASS" "$NVR_API/api/streams" > "streams-$(date +%s).json"; }
mark RAMP_START
n=0
for tier in "${TIERS[@]}"; do
  n=$((n + 1)); FILE=${tier%%:*}; CNT=${tier##*:}
  keys=$(seq 1 "$CNT" | sed "s/^/load-${FILE%.*}-n${n}-/")
  mark "S${n}_start"
  bash pushers.sh start "$RTMP" "$FILE" $keys
  sleep 60;  mark "S${n}_steady"
  sleep 180; snap; mark "S${n}_end"
done
mark RAMP_DONE
