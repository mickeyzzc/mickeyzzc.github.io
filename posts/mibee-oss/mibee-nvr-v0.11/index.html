MiBeeNvr v0.10.1 → v0.11.0: 飞牛安装修复 + GB/T 28181 国标接入 + 全天回放时间轴

August 17, 2026 August 27, 2026 MiBeeOSS NVR, Go, GB28181, 国标, SIP, 录像回放, 时间轴, 飞牛, FnOS, Docker, AGPL, 开源 MiBee 开源项目实践系列 2940 字 6 分钟阅读
🔊

v0.10.0 正式版发出去没几天，飞牛用户的反馈集中成一句话：装不上。我在一台 RK3582 的飞牛实机上前后装了七遍，加上 SSH 进容器翻日志，才把三个障碍逐个挖出来。上一篇发布帖还停在 v0.10.0-preview.1，正式版、补丁版到这次的 v0.11.0 拢共三个版本，这篇一起交代。

v0.11.0 本身重头是两块：GB/T 28181 国标接入，录像回放重做。另外许可证从 MIT 换成了 AGPL-3.0-only，升级前把文末那节看完。

飞牛安装修复

三个障碍，按用户撞上的顺序说。

第一个最直接：安装卡在拉镜像。当时的安装包是 docker-project 形态，装的时候从 ghcr.io 拉镜像，国内访问 ghcr 经常超时，网络一卡整个安装就挂在那里。

第二个费了点劲。装是装上了，点飞牛桌面图标没反应。查下来是 Web UI 发的 X-Frame-Options: DENY 把桌面的跨源 iframe 嵌入拒了。换成可配置的 CSP frame-ancestors，重装，还是打不开——http://* 这个值只匹配默认 80 端口，而飞牛桌面跑在 :5666 这种非默认端口上。改成协议源 http:/https:，任意端口放行，才算通。

第三个是飞牛自己的坑：文本框的 min/max 被当成字符串长度校验。端口填 9090，四个字符，直接拒收。换成 pattern 正则才过去。

v0.10.1 的最终方案是把安装和网络解耦：amd64、arm64 两份镜像 docker save 进 .fpk（160MB 上下），安装时本地 docker load，全程不联网。应用形态也从 docker-project 换成 native。这里有个时序问题——飞牛的 docker-project 应用在安装时就自动 compose up，这一步发生在任何生命周期钩子之前，离线镜像还没来得及 load 就先报 No such image。native 形态让应用自己的启动脚本管 load 和 run，顺序才摆得对。

v0.11.0 在这基础上做成双包，Docker 侧也加了国内镜像：

在线包只有几十 KB，启动时探测 ghcr 和阿里云 ACR 哪边延迟低就从哪边拉。Docker 镜像现在两边同步发，国内直接用这个地址：

1

docker pull registry.cn-hangzhou.aliyuncs.com/mickeybeehome/mibee-nvr:latest

一键安装脚本同样自动择优。Synology、QNAP、极空间的商店模板也在这版补上。

录像回放重做

录像按 30 秒一片存在磁盘上。回放时每播完一片要重新挂载下一个文件，中间黑屏闪一下；时间轴只在单片内有效，想回看一整天就得一片片点。这个问题从早期版本就有，一直没动，v0.11 重做了。

换段黑屏用双缓冲解决。主 <video> 播到 80% 时预取下一片，挂在一个待机的 <video> 上，ended 事件一触发，备用的直接顶上来，肉眼看不出切换。

mermaid
flowchart TD
    A[主 video<br/>播放中] -->|预取 80%| B[备用 video<br/>待机]
    B -->|ended 触发| C[瞬时接管<br/>无黑屏]
    style A fill:#2196F3
    style B fill:#FF9800
    style C fill:#4CAF50

时间轴这边做了个按需 fMP4 分片器，把一整天的录像接成一条连续时间轴。录像之间的空隙也能拖——上午十点断电四十分钟，时间轴上就是一段空白，直接拖过去，不会卡住。

AVI 录像加了帧浏览模式，可拖动、跨段无缝。VOD 分片 404 会自动重建，切换录像时做了 chunk 预取和日数据缓存。

GB/T 28181 国标接入

之前接海康、大华的摄像头，要么买他们的 NVR，要么部署专门的国标平台软件。这些设备其实都支持 GB/T 28181——视频监控的国标，走 SIP 信令，设备管理页里叫「平台接入」或「28181」。v0.11 让 MiBeeNvr 自己来当这个平台。

设备侧只要 REGISTER 过来，剩下的全自动：查目录、给每个通道建一张相机卡、INVITE 拉流、开始录像。

mermaid
flowchart TD
    A[海康/大华摄像头<br/>SIP REGISTER] --> B[MiBeeNvr<br/>SIP :5060]
    B --> C[目录查询<br/>Catalog]
    C --> D[通道自动入册<br/>gb- 相机]
    D --> E[INVITE 拉流<br/>录像 + 直播]
    style A fill:#2196F3
    style B fill:#9C27B0
    style C fill:#FF9800
    style D fill:#4CAF50
    style E fill:#4CAF50

注册之后的能力：PTZ 方向、变倍、预置位，语音对讲（浏览器麦克风直连设备扬声器），设备侧录像检索和回放（支持倍速、拖动），报警、目录、移动位置订阅。级联也能做——NVR 作为下级平台挂到上级国标平台下面，本机相机聚合成目录上报，上级点播时转发 RTP/PS，纯封装不转码，上级不需要任何特殊支持。

配置就三个必填项：

yaml

gb28181:
  enabled: true
  sip_listen: ":5060"
  server_id: "34020000002000000001"
  realm: "3402000000"
  password: "yourpassword"
  port_range: "30000-30050"
  media_transport: "udp"        # udp | tcp-passive | tcp-active

设备那边填 NVR 的 IP、5060 端口、一样的编号和密码，几秒内注册成功。完整参数见仓库的 config.example.yaml。

两件事要注意。password 留空就是不鉴权，能摸到 5060 端口的设备都能注册进来，公网部署务必设密码。另外这功能还是实验性的：代码按 GB/T 28181-2016 写，自研设备加模拟器互调都验过，海康、大华真机的全量回归还没做完，所以默认关闭，不开不影响任何东西。

其他更新

  • 局域网发现：NVR 首次启动生成一个 UUID 持久化，/api/health 里带着 device_id 和 device_name，客户端认设备不认 IP，NVR 换 IP 不再断连。发现走两条路：mDNS 通告 _mibee-nvr._tcp，加一个 UDP 49090 广播应答器，兜住组播受限的网络
  • App token：mbv_ 前缀的密钥按设备发，单独撤销、热加载、带最近使用时间。给 Home Assistant 这类集成发一个专用 token，收回时不用动全局密码
  • iOS 上带鉴权的 HLS 会 401 的问题：播放列表请求现在下发一个作用域受限的 mbs_session cookie，AVPlayer 这种没法逐请求带头的播放器就通了
  • WebRTC 音频零转码：G.711 和 Opus 直接复用进 WebRTC 轨道，不再过一遍转码
  • 初始化向导改为增量写入凭据，预置的监听地址、AI 后端配置、摄像头列表不会再被清掉
  • 两路异常国标流把宿主内存吃爆的事故修了，PES 重组缓冲加了上限
  • 国标直播冻结：长 GOP 会话回收，陈旧 WebRTC hub 绑定清理

许可证变更

v0.11.0 起从 MIT 换成 AGPL-3.0-only，v0.10.1 及更早版本永久保持 MIT。各场景的影响：

你的用法影响
只是使用/运行（含商用）零义务，和以前一样
分发修改版修改版必须以 AGPL-3.0 开源
基于 pkg/ 扩展接口构建独立程序不受影响，有链接例外
独立进程通过 HTTP/WebSocket 调用运行中的 NVR完全不受影响

对绝大多数人就是没影响：跑起来、录像、看流，零义务。需要开源的只有一种情况——改了代码还分发出去。

GET /api/cameras/{id}/protocols 的响应字段改成了 snake_case，和其它端点保持一致：

旧字段新字段
Protocolprotocol
Availableavailable
Reasonreason

调这个端点的脚本要跟着改。

纯 HTTP 下 AAC 直播音频降级了。FAAD2 的 WASM 回退是 GPL-2.0，为了许可证干净移掉了，AAC 直播预览现在需要 WebCodecs，也就是 HTTPS 或 localhost。G.711 直播和录像里的 AAC 不受影响。

数据库不用迁移，国标相关的新表首次启动自动建。

# 一键安装（amd64 / arm64 / armv7，自动择优镜像源）
curl -fsSL https://raw.githubusercontent.com/Mi-Bee-Studio/MiBeeNvr/main/install.sh | sudo bash
