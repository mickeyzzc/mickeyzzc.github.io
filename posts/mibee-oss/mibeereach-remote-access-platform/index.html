MiBeeReach：把远程桌面、终端、SSH 和隧道装进一个二进制

November 3, 2026 November 4, 2026 MiBeeOSS Rust, 远程桌面, QUIC, WebRTC, 内网穿透, 自部署, 隐私 MiBee 项目实践系列 2406 字 5 分钟阅读
🔊

我对商用远程软件的不满是具体的：免费档限速限额度，广告按时段弹，流量过厂商的服务器，画质和延迟没有一处是我能调的。向日葵和 ToDesk 都用过一阵，自建 RustDesk 服务版也评估过，最后决定从零写一个。这就是 MiBeeReach：Rust 写的单二进制远程接入平台，远程桌面、远程终端、远程 SSH、内网穿透隧道和 P2P 跨网全在里面。名字取自 MiBee 品牌加 Reach（触达）——让任意内网机器按你的意愿从外网可达。

能力面：远程操作的一个入口

能力说明
远程桌面视频 + 输入 + 剪贴板（文本/图片/文件）+ 桌面音频 + 文件互传 + 多显示器 + 只读模式
远程终端远程 shell（ConPTY / PTY），局域网直连或 P2P
远程 SSH内置 SSH server，标准 ssh 客户端直连
内网穿透隧道内网 TCP 端口经流中继暴露，支持按流目标
管理控制台图形界面：连接档案 / 工作区 / 内嵌终端 / SSH 页签 / 设备绑定

被控端是 Windows 和 Linux（Wayland），主控端是 Windows 和 macOS。所有能力共享同一个传输抽象和同一套设备身份——加一种能力（终端、SSH、隧道）不是叠一个新产品，而是在同一条连接的协商机制上多声明一种流类型。两端各自声明支持的能力，在交集内开工；数据流靠类型标签路由，不靠打开顺序隐式配对。

传输设计：一条连接，两种流

远程桌面最大的传输难题是丢包。视频帧天然「最新的最有价值」，丢一帧的代价只是那一帧的空隙；等重传的代价是后面所有帧排着队延迟——队头阻塞。输入、剪贴板、文件正相反，一个字节都不能错序。所以 Reach 在同一条 QUIC 连接上给两类流各配了各自的投递语义：

视频链路是：屏幕采集 → 编码 → 帧内分片 → datagram 直发 → 接收端重组解码上屏，前向纠错和重组都在协议层处理。跨网路径上视频走协商出的无序数据通道，对端不支持时自动回落有序通道——回落保证弱网下会话仍然可用。

局域网之外：自部署 P2P 底座

局域网直连之外，跨网走的是自部署的 P2P 底座：信令、STUN、TURN 和数据面全套自己控。设备用配对码绑定——配对一次，设备凭据落盘，之后的会话走设备自己的签名身份，令牌自动续期。主控端同时拿到局域网地址和 P2P 地址时自动选优：先探测局域网直连，失败再落回 P2P。

底座按产品、账号、设备三层命名空间隔离，跨租户互不可见。数据面即使是中继路径也不看明文，端到端加密是硬约束——这是当年评估「要不要租现成穿透服务」时给自己画的底线：画质延迟可控是自研的回报，流量路径可控是自部署的回报，两样都不能打折。

安全模型

局域网路径：QUIC 的自签 TLS 只解决加密不解决认证，Reach 在传输层之上叠了一道 PSK 挑战-应答门——没有配对密钥的连接直接拒之门外，配对过的设备零弹窗直连，密钥一条命令生成或重置。

跨网路径：平台层令牌认证加设备端 Ed25519 签名握手，数据面 DTLS。

会话内：权限掩码（控制、剪贴板、文件互传）由被控端强制；只读模式经配置帧下发生效；远程会话进行时本地屏幕置黑——省流量，也避免旁人看到会话内容。

资源与画质

远程桌面常驻的开销主要是编码器和采集循环。Reach 对静止画面做了两层收敛：画面不动时采集间隔指数退避，连续多轮静态后释放编码器，新帧一到立即恢复满速；背景置黑本身也省掉了整屏编码。结果是被控端空载时 CPU 占用从两位数落到接近零，树莓派 400 这一档的板子可以长期挂着当被控端。

画质与延迟可调是自研的回报：帧率、采集缩放、捕获超时都是运行参数；编码器在软编和 AMD 硬编之间可选，硬件支持时单帧编码耗时可砍半以上。弱网行为也在设计里：QoS 探针驱动降档状态机，码率撑不住时先降帧率再降分辨率。

从零写，不套壳

Reach 没有站在任何现成远程方案上。屏幕采集自己写：Windows 走 DXGI Desktop Duplication 的零拷贝路径，Linux 走 Wayland 三后端按会话环境自动选。编码自己封装：openh264 软编打底，AMD AMF 硬编作为可选构建。渲染、输入注入、剪贴板、音频采集都是平台专有实现，按 Windows/Linux/macOS 拆成独立模块，业务层经平台别名访问，跨平台零改动。

依赖管理有明确的纪律：许可证宽松（MIT / Apache / BSD）的库直接用，quinn、russh、openh264、Tauri 都在这张清单上；copyleft 许可证的项目只读设计和算法，代码一行不搬。对闭源分发这不是风格偏好，是合规前提。

一个二进制的形态

reach 是单个可执行文件，能力按子命令域展开：

reach desktop host     --bind 0.0.0.0:7777     # 被控端
reach desktop connect  --host 192.168.1.10:7777 # 主控端
reach terminal connect --host 192.168.1.10:7778
reach ssh host                                  # 标准 ssh 客户端直连
reach tunnel connect   --local 127.0.0.1:8080 --target 127.0.0.1:80
reach ui                                        # 图形控制台

被控端安装包是一个纯托盘进程；主控端控制台用 Tauri 做低频配置与会话管理——连接档案、内嵌终端、SSH 页签、设备卡片都在里面。视频画面走原生窗口渲染，绝不经过控制台的进程间通信：图形界面的 JSON 桥扛不住视频帧吞吐。

工作室现在用它接管树莓派、内网里的测试机和个人笔记本。限速、广告、隐私这三笔账，自己部署一遍之后就都不存在了。
