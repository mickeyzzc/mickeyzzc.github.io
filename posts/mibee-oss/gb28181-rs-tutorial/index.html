gb28181-rs 教程：用 Rust 把设备注册到国标平台

October 1, 2026 MiBeeOSS Rust, GB28181, 监控摄像头, 开源 MiBee 开源项目实践系列 4505 字 10 分钟阅读
🔊

gb28181-rs 是 GB/T 28181 设备端（UAC）的 Rust 实现：把一台媒体源注册到国标平台、向它推流、接平台下发的控制。它与 gb28181-go 是孪生设计——同一份职责的两种语言实现，PTZ 位解码、对讲 SDP、快照这些线上字节共享同一张 golden 表，谁的封装改了谁先红。库的出身是 MiBee 的 Rust 相机固件，每天在生产环境里跑。

这篇按「能直接抄去用」的标准写：先零硬件跑通，再从 cargo new 写出完整的宿主程序，每个注入缝给完整实现，读完就能在自己项目里落地。

crates.io 上当前是 0.12.0，要求 Rust 1.80（MSRV，CI 有专门 job 盯着）。运行时基于 tokio；可选 feature 只有一个：gb35114（国密 A 级），它拉入 SM2/SM3 依赖，需要 Rust 1.85 以上才编得过，MSRV 本身不变。注意一点：README 的 Usage 代码块里写的版本号偏旧，以 CHANGELOG 和 crates.io 为准。

零硬件先跑通

写代码之前，先看库自己怎么跑——device_demo 是一个进程内互操作演示，自带一个手写的假平台（SIP server 加 RTP 接收器），走完 REGISTER → 401 digest 挑战 → 鉴权重注册 → Catalog → INVITE → RTP/PS 收流解回 NALU → BYE 的完整闭环，全程断言，退出码 0 就是全过：

console
1

cargo run --example device_demo

不用真平台、不用真相机，一台开发机就能验证协议栈是通的。另外三个示例各有分工：playback_demo 演示录像查询与回放控制（RecordInfo → 回放 INVITE → PAUSE/倍速 → BYE），ps_mux 演示离线 PS 封装解包（无网络），manscdp_demo 演示纯消息层编解码。

use gb28181_rs::{AccessUnit, FrameSource, FrameSubscription};
use std::collections::HashMap;
use std::sync::atomic::{AtomicU64, Ordering};
use std::sync::Mutex;
use tokio::sync::mpsc;

struct CaptureBus {
    next_id: AtomicU64,
    subs: Mutex<HashMap<u64, mpsc::Sender<AccessUnit>>>,
}

impl CaptureBus {
    fn new() -> Self {
        Self { next_id: AtomicU64::new(1), subs: Mutex::new(HashMap::new()) }
    }

    // 采集侧广播：满即丢，永不阻塞编码器
    fn broadcast(&self, au: AccessUnit) {
        let subs = self.subs.lock().unwrap();
        for tx in subs.values() {
            let _ = tx.try_send(au.clone());
        }
    }
}

impl FrameSource for CaptureBus {
    fn subscribe_with_capacity(&self, capacity: usize) -> FrameSubscription {
        let id = self.next_id.fetch_add(1, Ordering::Relaxed);
        let (tx, rx) = mpsc::channel(capacity.max(2));
        self.subs.lock().unwrap().insert(id, tx);
        FrameSubscription { id, receiver: rx }
    }

    fn unsubscribe(&self, id: u64) {
        self.subs.lock().unwrap().remove(&id);
    }
}

两条语义约定在这段代码里就能看清：subscribe_with_capacity 返回的 FrameSubscription{id, receiver} 带一个有界通道，capacity 按惯例给 2，慢订阅者丢帧、永不阻塞采集侧；INVITE 到来时库订阅一次、BYE 时 unsubscribe。

use gb28181_rs::{AccessUnit, Gb28181Config, Gb28181Server, Nalu};
use std::sync::Arc;
use std::time::{Duration, Instant};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let mut config = Gb28181Config::default();
    config.enabled = true; // 库本身不读它，宿主自己据此决定是否启动
    config.platform_sip_address = "192.168.1.10".into();
    config.platform_sip_port = 5060;
    config.device_id = "34020000001320000001".into(); // 20 位国标编码
    config.channel_id = "34020000001310000001".into();
    config.sip_domain = "3402000000".into();
    config.password = "your-platform-password".into();
    config.heartbeat_interval_secs = 60;
    config.heartbeat_timeout_count = 3;

    let bus = Arc::new(CaptureBus::new());

    // 采集任务：换成你的编码器输出。这里用合成帧演示形状。
    let feed = bus.clone();
    tokio::spawn(async move {
        let mut i = 0u64;
        loop {
            i += 1;
            let key = i % 25 == 0;
            let au = AccessUnit {
                nalus: if key {
                    vec![
                        Nalu { nalu_type: 7, data: vec![0x67, 0x42], is_idr: false, is_sps: true, is_pps: false, is_aud: false },
                        Nalu { nalu_type: 8, data: vec![0x68, 0xEB], is_idr: false, is_sps: false, is_pps: true, is_aud: false },
                        Nalu { nalu_type: 5, data: vec![0x65, 0x01], is_idr: true, is_sps: false, is_pps: false, is_aud: false },
                    ]
                } else {
                    vec![Nalu { nalu_type: 1, data: vec![0x41, 0x02], is_idr: false, is_sps: false, is_pps: false, is_aud: false }]
                },
                timestamp: Instant::now(),
                is_key_frame: key,
            };
            feed.broadcast(au);
            tokio::time::sleep(Duration::from_millis(40)).await; // 25 fps
        }
    });

    let mut server = Gb28181Server::start(config, bus.clone(), None).await?;
    // 到这里设备已上线：注册、保活、目录、INVITE 应答全在后台运行

    tokio::signal::ctrl_c().await?;
    server.shutdown_with_deregister().await?; // REGISTER Expires: 0，走完整 401 流程下线
    Ok(())
}

逐段说：

  • Gb28181Config 是 serde 友好的，TOML 和 JSON 同形——上面的字段赋值等价于一份 config.toml 反序列化。platform_sip_address、device_id、password 是三件必改的事，库对这三件有启动检查（见下节）。
  • Gb28181Server::start(config, hub, recordings) 绑定 SIP socket 后进入后台运行，返回的 ServerHandle 带 #[must_use]——直接丢掉它服务器就没人管了。退出时 shutdown() 是快停（注册自然过期），shutdown_with_deregister() 先发 REGISTER Expires: 0 走完整的 401 流程再下线。
  • 帧类型 AccessUnit{nalus, timestamp, is_key_frame}、Nalu{nalu_type, data, is_idr, is_sps, is_pps, is_aud}：data 是不带 Annex-B 起始码的裸 NAL 载荷，SPS/PPS 跟 IDR 一起喂，is_key_frame 如实标——它影响 RTP 时间戳和平台侧起播等待。
  • 本地录像在跑时调用 gb28181_rs::set_record_active(true)，平台查 DeviceStatus 会如实报 <Record>ON</Record>。

不想手写采集总线，测试时直接用库自带的 gb28181_rs::MockFrameHub（有界通道、写满即丢，new()/write(&AccessUnit)/subscriber_count()）。

use gb28181_rs::{RecordingSource, SegmentMeta};

struct FsIndex;

impl RecordingSource for FsIndex {
    fn lookup(&self, start_ms: u64, end_ms: u64) -> Vec<SegmentMeta> {
        // 查自己的录像库，返回与区间有重叠的段（闭区间语义）
        vec![SegmentMeta {
            file: "/records/1430.mp4".into(),
            start_ms: 51_600_000,
            end_ms: 54_000_000,
        }]
    }
}

// 接入时把 Some(Arc::new(FsIndex)) 传给 start 的第三个参数
let server = Gb28181Server::start(config, bus, Some(Arc::new(FsIndex))).await?;

Lookup 返回时间段内有重叠的段，库负责把回放 INVITE 变成按段匀速读出、按真实节奏封包发送，播完自然结束发 MediaStatus: Play Finished（下载是 Download Finished）；SIP INFO 的播放控制（暂停/倍速）也在库内处理。段的读文件由宿主实现（resolve_path 有默认行为）。跑 cargo run --example playback_demo 能看到整条回放链路的交互序列。

use gb28181_rs::manscdp::PtzCommand;

struct Controls;

impl gb28181_rs::DeviceControlHandler for Controls {
    fn on_force_iframe(&self) { /* 让编码器立即出 IDR */ }
    fn on_ptz(&self, cmd: &PtzCommand) { /* 位级解码后的 PTZ，驱动云台 */ }
    fn on_record(&self, start: bool) { /* 手动录像开停 */ }
    fn on_guard(&self, arm: bool) { /* 布防/撤防 */ }
    fn on_teleboot(&self) { /* 远程重启 */ }
    // on_reset_alarm / on_home_position / on_drag_zoom 同理按需覆写
}

server.with_control_handler(Arc::new(Controls));

DeviceControlHandler 覆盖强 I 帧、录像、布防撤防、报警复位、远程重启、PTZ 位级解码（与 Go 孪生共享同一张 golden 字节表）、DragZoom、HomePosition；DeviceConfigHandler 接基础参数、帧镜像、报警上报配置。不给回调的命令维持显式拒绝应答，平台能看到设备不支持。

2022 版与 X-GB-Ver

GB/T 28181-2022 的协商开关就是一个配置字段：

rust
1

config.protocol_version = Some("3.0".to_string()); // 2022；"2.0" = 2016

设了之后每条 REGISTER（初始和鉴权重发）都带 X-GB-Ver 头，平台宣告的版本从 server.platform_protocol_version() 读；不设置则线格式与 2016 逐字节一致，这是默认。2022 的五组信息查询（HomePosition、CruiseTrack 等）和快照、订阅通知、广播都有最小应答。REGISTER 应答里的 SIP-Date 会在 server.platform_date_unix() 暴露——校时只观察，设不设钟是宿主的事。

生产项目里的用法

这个库本身就是生产代码：从 MiBee 的 Rust 相机固件原样抽出，现役宿主是 mibee-eye-rs 和 mibee-eye-notebook。按功能对照：

功能生产项目用法
FrameSource 喂帧 / 注册保活 / INVITE 推流mibee-eye-rsV4L2 采集加 M2M 硬件或 openh264 软件编码，编码输出直接喂库，常驻内存约 6 MB 的完整国标相机
控制回调 / 2022 协商 / 录像回放mibee-eye-rs设备端全套：PTZ/强 I 帧回调接相机控制，protocol_version 开 2022，RecordingSource 接本地录像
对讲 / 麦克风上行mibee-eye-notebookPC 的摄像头和麦克风变成一台国标设备，with_talkback_source 接系统麦克风，GB 35114 安全特性也在它上面开着跑

看完整实现：mibee-eye-rs 是「Linux 板子变国标相机」的完整答案——采集、编码、喂帧、注册、推流、回放一条龙，本篇的每个接缝在它里面都有对应模块；mibee-eye-notebook 则演示了同一套库跑在 PC 上的形态（浏览器 TLS 管理页、RTSP/RTMP/ONVIF/GB28181 多协议并存）。与 Go 孪生（gb28181-go）对练时，两端线上字节按共享 golden 表对齐，拿任一侧当平台或设备都能咬合。
